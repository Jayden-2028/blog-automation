# person-researcher — 인물 백과 자료조사 규격 (확정 v4.1, 2026-10-15)

> 위치: `prompts/research/person-researcher.md`
> 상태: **확정** (2026-10-15 사용자 통과, prod 배치)
> 상위 설계: `PERSON-PROFILE-TRACK-2026-10.md` · 재설계 발주 `PERSON-PROFILE-REDESIGN-2026-10.md` **§4**
> 원고 규격: `prompts/writing/style/person.md` **v3**

## 0. 이 규격이 `researcher.md`를 대체한다

**`job.category === "person"`이면 이 파일만 읽는다.** `researcher.md`와 그 §4-1의
`celebrity` 프로파일은 읽지 않는다. 브리프의 `type` 판정(`BRIEF_TYPES`에 `celebrity`가 있다)에
맡기면 기존 프로파일이 선택되므로, **category로 분기해야 한다.**

**이 파일은 self-contained다.** 실행자는 `researcher.md`를 읽지 않으므로, 거기 있던 절대
규칙·허용 문형·frontmatter 형식을 이 파일에 직접 적어 뒀다. 다른 파일을 찾아갈 필요가 없다.

### 0-0. v4가 뭘 바꿨나 — 깊이는 작문이 아니라 조사에서 나온다

v3로 만든 파일럿 1편(김지원)이 **사용자 평가 50점**을 받았다. 원인은 원고가 아니라 이 규격이다 —
v3는 **사실(작품·연도·배역·수치) 수집 위주**였고 **정성 재료를 수집하라는 지시가 없었다.** 재료가
수치뿐이면 원고도 수치 나열이 된다.

v4는 다음을 추가한다. **정성 재료 수집이 사실 수집과 동급의 1급 목표다**(§3).

- **작품별 조사 라운드 의무화** (§2-6): 대표작마다 별도 검색 라운드 → "작품별 카드" 출력
- **정성 재료 1급 목표** (§3): 리뷰·평론의 **인용문 원문**, 명장면·명대사, 화제가 된 순간
- **과거·일화 조사 각도 신설** (§2-7): `배우 <이름> 과거` / `어릴 적` / `데뷔 초` / `일화` / `인터뷰`
- **나무위키 `기타`(여담·인터뷰·주변의 한마디)를 정성 재료 1급 수집처로 지정** (§2-1)
- **예능·광고는 "가장 이슈가 된 포인트"를 찾는다** (§2-8)
- **검색 횟수 하한 대폭 상향** (§2-2, §8) 및 **verdict 판정식 재설계** (§6-1)

### 0-0-1. v4.1이 뭘 바꿨나 (2026-10-15 사용자 결정, 발주 §4-2)

**조사 절차·verdict 판정식·출력 형식은 무변경이다.** 바뀐 것은 **수집한 재료를 원고에서
어떻게 쓸 수 있는지**를 적는 네 자리뿐이다.

1. **위키 단독 사실·수치의 단정 서술 허용** (§1 순위표·§1-1 등급표·허용 문형).
   "이미 많은 사람들이 리뷰한 문서이기 때문에 오류 확률은 감수한다"(사용자 원문).
   → **§9-1에 "교차 전이라 제외"를 쓰지 않는다.** v4 실측에서 이 사유로 빠진 수치가
   5건(눈물의 여왕 24.9%, 태양의 후예 38.8%, 쌈 마이웨이 13.8%, 나의 해방일지 6.7%,
   유 퀴즈 5.1%)이었다 — 이제 전부 쓸 수 있다.
2. **화자 전환에 따른 허용 문형 교체** (§1-1). 원고 화자가 "작품을 봐 온 OTT 마케터"로
   재정의되어 `~라는 평이 나왔어요` 헤지 의무가 폐지됐다(`person.md` v3). research는
   **인용 원문을 그대로 모으는 일만** 하고, 원고 문형은 `person.md`가 정한다.
3. **매체명 귀속을 평가 동사에 한해 허용** (§1-1).
4. **마이크로 수치는 수집하되 원고에 쓰지 않는다** (§3-2). "한 문단에 수치 하나" 상한도
   폐지됐다.

### 0-1. 절대 규칙 (위반 시 산출물 폐기)

**v4의 조사 확대는 이 9개를 흔들지 않는다. 깊이는 "수집량"으로 내고, 지어내기로 내지 않는다.**

1. **확인 안 된 내용은 쓰지 않는다.**
2. **AI의 추측을 쓰지 않는다.** 학습된 지식으로 채우거나 검색 결과에서 "아마 이럴 것"이라고
   추론한 내용을 기록하지 않는다. 출처 문서에 쓰여 있는 것만 옮긴다.
3. **모든 정보 줄에 출처 URL을 붙인다.** URL이 없는 문장은 파일에 넣지 않는다. 예외 없음.
4. **URL은 실제로 열어 확인한 것만 적는다.** 검색 결과 스니펫만 보고 본문 내용을 추정하지 않는다.
5. 인물명이 오타로 보여도 고치지 않는다. 그대로 조사하고 파일 하단에 그 사실을 남긴다.
6. **등급을 숨기지 않는다.** 커뮤니티·블로그 근거는 반드시 그렇게 표시한다. 판정이 안 되면
   최하위(`community`)로 적는다.
7. **날짜를 적는다.** 발행일과 확인일 둘 다 남긴다.
8. **모르면 적지 않는다.** 해당 내용을 빼고 구성한다. 빈칸을 추정으로 채우지 않는다.
9. **이름은 공식 채널에서 다시 확인한다.** 인물 트랙에서 가장 중요한 규칙이다 — 인물명·배역명·
   극단명·소속사명이 전부 이름이고, 1차 출처는 네이버 인물DB다(§1 순위 1).

> **정성 재료에도 그대로 적용된다.** 평가·장면·인용문도 §0-1 3·4번을 지킨다 — 인용문은
> **원문을 그대로** 옮기고 URL을 붙이며, 열지 않은 기사의 평가를 요약해 적지 않는다.
> research에 없는 정성 서술은 원고에 못 쓴다.

## 1. 출처 우선순위 (위에서부터 채택)

**자료조사는 아래 전부를 돈다.** §5 레퍼런스 블로그는 **서치풀의 일부일 뿐**이고 자료조사의
전부가 아니다(2026-10-13 사용자 지시). 레퍼런스만 보고 조사를 끝내면 그 블로그들이 다룬 범위
안에 갇힌다 — 인물DB·위키·뉴스·웹검색·LLM 보강으로 **최대한 풍성하게** 모은 뒤, 레퍼런스는
주제 선정을 교차검증하는 데만 쓴다.

| 순위 | 소스 | 이 소스가 결정하는 것 |
|---|---|---|
| 1 | **네이버 인물DB** (인물 검색 결과) | **현재 소속사, 생년, 신체, 작품별 배역명과 중요도(주연/특별출연), 수상.** 다른 출처와 다르면 이쪽을 쓴다 |
| 2 | **나무위키** | 필모그래피 전체, 데뷔 기록, 수상, **단독 시청률·기록 수치**, 여담·논란 타임라인, **그리고 `기타`의 인터뷰 발언·주변의 한마디**(§2-1). **단독이어도 단정 가능**(§1-1) |
| 3 | **위키백과** | 1·2와 대조. 나무위키에 없는 공식 표기. **단독이어도 단정 가능**(§1-1) |
| 4 | 언론 보도 | 시점·세부·발언 인용. **리뷰·평론 기사가 정성 재료의 1순위다**(§3). 2곳 이상 일치해야 단정 |
| 5 | 공식 발표 (소속사·제작사·공식 SNS) | 최신 작품·활동 |
| 6 | **레퍼런스 블로그 10곳** (§5) | 주제 선정 교차검증. **사실 근거로는 쓰지 않는다** |

**커뮤니티는 쓰지 않는다**(2026-10-13 사용자 결정). theqoo는 비로그인 검색이 작동하지 않고,
fmkorea robots는 `ClaudeBot`·`anthropic-ai`를 차단하며, ruliweb robots는 `/search`를 막는다.
수집이 불가능하므로 인용하지 않는다.

### 1-1. 등급 표기

파이프라인의 `SourceAuthorityLevel` 4등급(`official`/`medical`/`news`/`community`)을 그대로
쓴다. **새 등급을 만들지 않는다.** 인물 주제에서는 실질적으로 셋이다.

| 등급 | 대상 | 원고에서의 서술 강도 |
|---|---|---|
| `official` | 네이버 인물DB, 소속사·제작사 공식 발표, 공공기관, 네이버 자동완성 원본 | 단정 서술 |
| `news` | 언론 보도. **2곳 이상 일치해야** 단정 | 출처 표시 없이 사실로 단정. "보도됐다" 류는 원고 금지 |
| `community` | **나무위키·위키백과** | **단독 근거로도 단정 서술**(2026-10-15 결정). 인물DB와 값이 충돌하면 인물DB가 이긴다 |
| `community` | 블로그·개인 사이트·커뮤니티 | **사실 근거로 쓰지 않는다**(§1·§5). 위키와 같은 등급이지만 취급이 다르다 |

**허용 문형 (원고 단계에서 쓸 수 있는 형태 — 2026-10-15 전면 갱신)**

- **위키 단독 사실·수치를 그냥 단정한다**(v4.1 변경). 교차확인은 요구하지 않는다. 나무위키
  단독 시청률도 쓴다. **유지되는 예외 셋**: ① 인물DB와 값이 충돌하면 **인물DB가 이긴다**
  (§1 순위) ② 열애·사생활·논란은 `news` 2곳 이상(§4-3) ③ 비공인 가족·미성년 금지(§4-3).
- **나무위키를 주어로 쓰지 않아도 된다** — 그냥 사실로 쓴다. 주어로 쓸 수도 있지만
  (`"나무위키는 ~라고 소개한다"`), `"~에 따르면"`은 금지다(`core-rules.md` §1 공통).
- **평가·반응(§3)의 헤지는 폐지됐다**(v4.1 변경). `~라는 평이 나왔어요` / `~라는 이야기가
  많아요`는 **더 이상 기본 문형이 아니다.** 원고 화자가 "작품을 봐 온 OTT 마케터"로
  재정의되어 **확인된 평가를 화자의 문장으로 단정**한다(`person.md` v3 화자 절).
  → **research가 할 일은 변하지 않는다**: 평가의 **원문과 URL을 그대로 모은다**(§3-1).
    원문이 없으면 원고가 그 평가를 쓸 수 없다는 규칙도 그대로다.
- **매체명 귀속은 평가 동사에 한해 허용**(v4.1 변경, 2026-10-15 Q1 판정). `"〈매체명〉은
  ~라고 평했다/썼다/적었다/꼽았다"`는 **person 한정으로** 쓸 수 있다 — research에 인용
  원문 + URL이 있을 때만. `core-rules.md` §1-1이 막는 **"보도했다·전했다·~라는 소식·
  보도에 따르면"은 그대로 금지**다. 평가가 엇갈려 누가 그렇게 봤는지가 중요할 때 쓰는
  도구이고 기본 문형이 아니다.
- **인물 본인의 발언은 그대로 인용한다** — `"…"고 말했어요` 형태. 발언은 사실이고(그가 그렇게
  말한 것은 확인됐다) 평가가 아니므로, 헤지 없이 쓴다. **정성 깊이의 가장 안전한 재료다.**
  발언 서술 동사는 원고에서 돌려쓰므로(말했다/답했다/털어놨다/남겼다/꼽았다) research는
  **누가 어디서 한 말인지**를 정확히 적어 둔다.

> **각주 (구현 세션 오독 방지)**: 이 규격이 네이버 인물DB를 `official`로 두는 것은 **규격의
> 정의**이고, `sourceAuthorityRules.ts`의 도메인 판정(`.go.kr`/`.or.kr`/`.re.kr`)과는 다르다.
> 코드가 리서치 파일의 등급을 재계산하지 않으므로 충돌하지 않는다.

## 2. 수집 절차 — 전 단계를 빠짐없이 돈다

위에서 충분히 찾았다고 아래를 건너뛰지 않는다. 기록할 때만 §1 우선순위로 채택한다.

### 2-1. 고정 출처 (반드시 연다)

1. **네이버 인물DB** — 인물 검색 결과. 소속사·생년·신체·**작품별 배역명과 중요도**·수상을 여기서
   확정한다. **`함께 출연한 다른 인물` 섹션은 §4-1-1 동명이인 판정 도구**이고, `같은 이름 다른
   인물` 목록은 동명이인 수를 알려 준다.
   접근: `https://search.naver.com/search.naver?query=<인물명>+<직업>` (Chrome UA curl로 열린다.
   `terms.naver.com` 직접 접근은 차단될 수 있다.)
2. **나무위키** — `<인물명> 나무위키`로 검색해 **실제로 연다.** 검색 스니펫으로 대체하지 않는다.
   **다음 섹션을 전부 읽는다:**
   - `생애` — 출생·학창·캐스팅 경위. **§2-7 과거·일화 문단의 1차 재료다**
   - `출연 작품` — 필모그래피 전체(연도·배역·관객수·시청률)
   - `수상 경력` — 시상식·부문·작품
   - **`기타 > 여담`** — 별명·취향·일화. 정성 재료
   - **`기타 > 인터뷰`** — **인물 본인의 발언 원문이 여기 모여 있다.** 출처 매체·호수까지 적혀
     있어 그대로 인용할 수 있다. **v4의 핵심 수집처다**
   - **`기타 > 주변의 한마디`** — 동료·감독의 평가
   - 하위 문서(`/활동`, `/광고 및 화보`, `/콘텐츠`)가 있으면 그것도 연다
3. **위키백과** — 1·2와 교차확인. 공식 표기, 나무위키에 없는 항목.

### 2-2. 뉴스 검색 — **각도를 바꿔 최소 8회**

v3의 "최소 3회"로는 탐사식 범위가 나오지 않는다(발주 §2-2). 아래 각도를 전부 돈다.

- `<인물명>` 단독 — 최근 6개월 우선
- `<인물명> + 현재 화제작` — 배역·제작발표회·연기 준비
- `<인물명> + 현재 화제작 + 리뷰 / 호평 / 평가` ← **정성 재료용. 반드시 돈다**
- **대표작마다 1회 이상** — §2-6 작품별 라운드
- `<인물명> + 수상`
- **§2-7 과거·일화 각도 5종**
- **§2-8 예능·광고 각도**
- §4에서 선정된 작품 외 활동 주제별 질의

### 2-3. 웹검색 일반 (빈칸 보강)

2-1·2-2에서 채워지지 않은 항목을 웹검색으로 메꾼다. 작품 공식 페이지, 제작사·방송사 소개,
시상식 공식 기록, 영화관입장권통합전산망(KOBIS) 관객 수, 포털 작품 페이지가 여기 들어온다.

### 2-4. LLM 보강 (WebSearch / WebFetch)

고정 출처와 뉴스로 답이 안 나온 질문은 에이전트가 직접 검색하고 **URL을 열어** 확인한다.
특히 다음을 맡는다.

- 작품 내 캐릭터의 서사상 기능 — 공식 인물소개와 회차 정보를 대조해 정리
- 데뷔·수상 기록의 출처 간 불일치 원인 — 각 출처를 열어 기준이 무엇인지 확인
- **정량 지표가 없는 작품의 캐릭터 리뷰 탐색** (§3-1)
- 작품 외 활동 후보의 사실 확인 (§4-2)

**실물을 연다.** 작품·영상·화보가 화제의 실체면 그 **소개 기사가 아니라 실물**(공식 클립,
공식 게시물, 작품 페이지)을 연다.

**지어내지 않는다.** §0-1 절대 규칙이 그대로 적용된다.

### 2-5. 선정과 교차검증

1. 정량 반응을 찾는다 (§3-2). **그리고** 정성 재료를 찾는다 (§3-1). **둘은 양자택일이 아니다.**
2. 작품 외 활동 주제를 선정한다 — 네이버 자동완성 기준 (§4).
3. **레퍼런스 블로그에서 교차검증한다** (§5). 이 단계는 **마지막**이고, 앞 단계를 대체하지 않는다.

### 2-6. 작품별 조사 라운드 (v4 신설 — 필수)

**대표작으로 고른 작품마다 별도 검색 라운드를 돈다.** 한 번의 필모그래피 조회로 대표작 전체를
처리하면 작품 문단이 목록이 된다 — 그게 50점 원고의 구조적 원인이었다.

작품당 라운드 1회 = 질의 1~2개 + **열어 확인한 기사 1건 이상**. 채울 것은 셋이다.

| # | 채울 것 | 어디서 |
|---|---|---|
| ① | 배역명·중요도(주연/조연/특별출연)·캐릭터 한 줄 | 네이버 인물DB(1순위) → 나무위키 |
| ② | **가장 큰 후킹·매력 포인트** — 명장면·명대사·연기 변신·유행어 | 리뷰 기사, 종영 기사, 나무위키 `기타`, 배우 인터뷰 |
| ③ | **왜 이 작품이 대표작이 됐는지** — 평가·반응 근거 | 리뷰·평론 기사의 **인용문 원문** + 정량 지표 |

**출력은 §6-2 `## 3. 작품별 카드`다** — 작품당 블록 하나. 표가 아니라 블록으로 쓴다(표는 정성
재료를 담지 못한다).

**대표작 선정 기준**: 영화 + 드라마 + 예능을 섞어 **3~5개**. 정량 지표가 큰 것, 수상한 것,
인물 본인이 인터뷰에서 꼽은 것, 자동완성·레퍼런스가 함께 가리키는 것 순으로 고른다.

### 2-7. 과거·일화 조사 각도 (v4 신설 — 필수)

**"배우 <이름> 과거", "<이름> 어릴 적" 같은 각도가 이 포스팅의 큰 재료다**(사용자 피드백 7).
아래 5종을 **전부** 돈다.

| 질의 | 나오는 것 |
|---|---|
| `배우 <이름> 과거` | 데뷔 전·초기 활동이 재조명된 기사 |
| `<이름> 어릴 적` | 학창 시절, 캐스팅 경위, 가족 이야기 |
| `<이름> 데뷔 초` | 첫 CF·첫 작품 당시 보도 — **발행 연도가 오래된 기사를 일부러 찾는다** |
| `<이름> 일화` | 현장 비하인드, 동료 증언 |
| `<이름> 인터뷰` | 본인 발언. §2-1의 나무위키 `인터뷰` 섹션과 교차 |

**경계**: **공개 인터뷰·방송 발언·보도 기반만 쓴다.** 비공인 가족·미성년·일반인 지인은
§4-3 금지가 그대로 적용된다. 과거라고 해서 사생활 경계가 풀리지 않는다.

**실측(김지원, 2026-10-15)**: 이 각도에서 2011년 헤럴드경제 데뷔 초 기사(길거리 캐스팅 경위),
2026-09 서울신문(오란씨걸 재조명), 2026-09 텐아시아(아이돌 연습생 고백)를 얻었다. **15년 치
시간 폭이 한 섹션에서 나온다** — 최근 6개월 뉴스만 보면 통째로 비는 영역이다.

### 2-8. 예능·광고 조사 (v4 신설)

**회차 요약·제품명 나열이 아니다**(사용자 피드백 8·9).

- **예능**: 그 회차에서 **가장 이슈가 된 포인트 1~2개**를 찾는다. "예전 유행어를 다시 했다",
  "몰랐던 미담을 공개했다" 같은 단위다. 기사 제목이 그 포인트를 그대로 알려 준다.
- **광고·화보**: **제품이 아니라 그걸 입은/보여준 인물이 어땠나.** 보도자료 기사는 제품 스펙만
  적는 경우가 많다 — 그때는 인물 묘사 문장을 따로 찾고, **없으면 없다고 적는다**(지어내지 않는다).

**실측(김지원)**: 듀베티카 캠페인 기사 3곳 중 인물 묘사가 있는 것은 1곳("시크하고 모던한
스타일을 바탕으로"), 뉴시스 기사는 제품 스펙만 있었다. 그 차이를 §6-2 §7에 적어 뒀다.

## 3. 반응과 평가 — **정성 재료가 정량과 동급이다**

v3는 "정량 우선, 없으면 정성"이었다. **v4는 둘 다 모은다.** 정량은 근거로 한 번 쓰고, 문단의
중심은 정성이다(`person.md` §3). 정량만 모으면 원고가 수치 나열이 된다.

### 3-1. 정성 재료 — 1급 목표

**모을 것 (전부 원문 + URL)**

| 종류 | 설명 | 예(김지원 실측) |
|---|---|---|
| **리뷰·평론 인용문** | 기사가 연기를 평한 문장을 **원문 그대로** | "감정을 과하게 드러내기보다 차갑고 단호한 말투, 흔들림 없는 눈빛, 불필요한 망설임이 없는 행동으로 계수정이라는 인물을 완성했다"(스타데일리뉴스) |
| **명장면·명대사** | 회차·장면 단위로 특정 | X자를 그리며 "하지 않습니다"라고 말하는 시그니처 장면(iMBC) / "애라는 재미가 없을라 그래"(쌈 마이웨이 8회) |
| **본인 발언** | 인터뷰·방송에서 한 말 | "연기 점수는 50점이다. 50점은 그동안 캐릭터를 위해 노력했던 저에게 주는 노력 점수다"(2016 bnt 5월호, 나무위키 인터뷰 섹션) |
| **동료·제작진 평** | 감독·상대 배우의 말 | 이정림 감독 "병원이 하나의 조직이라는 점에 중점을 뒀다"(한국일보) |
| **화제가 된 순간** | 그 회차·캠페인에서 뭐가 이슈였나 | 유재석이 벌칙에서 빼주려 "이로 선물 포장지를 와악 뜯으셨다" 미담(TV리포트) |
| **반응의 '내용'** | 수치가 아니라 **무엇이 왜 호평·화제였나** | 예고 영상 댓글 "단발 김지원, 이거 하나로 끝"에 공감이 쏟아졌다(CBC뉴스). ※공감 수(약 2,800)는 research에만 적고 원고에는 쓰지 않는다(§3-2) |
| **비평의 아쉬움** | 호평만 모으지 않는다 | iMBC 리뷰 ★★★ — "통쾌함을 지속적인 몰입과 계수정 개인의 서사로 이어가야 한다" |

**찾을 곳 — 이 순서로 내려간다**

1. **기사형 리뷰·종영 기사에 실린 캐릭터 평** ← 1순위. 실측으로 여기서 대부분 나왔다
2. **나무위키 `기타 > 인터뷰` / `주변의 한마디`** ← 본인·동료 발언이 출처 표기와 함께 모여 있다
3. 배우 인터뷰 기사 (제작발표회·종영 인터뷰·매거진)
4. 포털 영화·작품 페이지의 관람평
5. 네이버 블로그 리뷰
6. 유튜브 리뷰 영상 댓글 ← **최후순위.** 익명 게시물이라 커뮤니티 폐기 취지와 경계가 가장
   가깝다. 1~5에서 재료가 나오면 내려가지 않는다

- **커뮤니티 게시판은 제외한다** (§1).
- **인용은 1~2문장 + URL 병기. 통째 전재 금지.**
- 서술 방식: 평가의 **내용**을 사실로 쓰지 않고, 그런 평가가 있었다는 것을 쓴다(§1-1 허용 문형).
  단 **본인 발언은 그대로 인용한다.**
- **호평만 모으지 않는다.** 별점·아쉬움 지적이 있으면 함께 적는다 — 원고가 홍보문이 되는 것을
  막는 유일한 장치다.

### 3-2. 정량 지표 — 근거로 쓴다

있으면 쓰고 없으면 그 자리를 비운다. 없는 것을 말로 채우지 않는다.

| 작품 종류 | 정량 지표 | 가용성 |
|---|---|---|
| 극장 영화 | 누적 관객 수 (KOBIS) | **대개 있다** |
| 지상파·케이블 드라마 | 회차별 시청률, **순간 최고 시청률** (닐슨·TNMS) | 있다. 단 방송 후 1~2일 지연 |
| OTT 오리지널 | 넷플릭스 주간 Top10 순위, **플랫폼 인기작·시리즈 부문 순위, 전주 대비 시청량 증가율** | **절대 시청자 수는 비공개지만 상대 지표는 공개된다** |
| 전 작품 | 수상·후보 기록, **화제성 조사 순위**(펀덱스·굿데이터 주차별) | 있다 |
| 예능 회차 | 회차 시청률, 동시간대·2049 순위 | 있다 |
| 광고·화보 | 앰배서더 발탁, 브랜드평판 순위 | 부분적 |

**정량은 문단의 중심이 될 수 없다**(`person.md` §3 ③). 단 **"한 문단에 수치 하나" 상한은
폐지됐다**(2026-10-15 결정) — 수치는 필요하면 넣는 **선택 재료**이고 개수를 세지 않는다.

- **위키 단독 수치도 수집하고 §4에 적는다**(v4.1 변경). "교차 전이라 제외"로 §9-1에 내리지
  않는다. 인물DB와 충돌할 때만 인물DB 값을 쓴다.
- **❌ 마이크로 수치는 원고에 쓰지 않는다** — 댓글 공감 수, 조회수 자릿수, 게시물 개수.
  research에는 **반응의 근거로 기록해도 되지만**, 원고는 "반응이 좋았다"를 여러 표현으로
  돌려쓴다(`person.md` v3 수치 절). 시청률·관객 수·순위·수상은 마이크로 수치가 아니다.

## 4. 작품 외 활동 — 대중이 가장 많이 찾는 것부터

**기사량으로 고르지 않는다**(2026-10-13 변경). 기사량은 기자의 관심이고, 우리가 쓸 것은
**일반 대중 시점에서 가장 잘 알려진 가십**이다.

### 4-1. 선정 3단계

1. **후보 풀** — 나무위키 여담·논란 섹션, 위키백과, 네이버 인물DB 연관 항목에서 주제를 모은다.
2. **순위 측정** — 네이버 자동완성(`fetchNaverAutocomplete`, 인물명 단독 질의)의 꼬리말을
   **주제 단위로 묶어** 센다. 같은 주제가 여러 꼬리말로 나오면 그만큼 가중한다.
3. **교차검증** — §5 레퍼런스 블로그에서 그 주제를 실제로 다뤘는지 본다. 다뤘으면 수요 확인,
   10곳 모두 안 다뤘으면 순위를 내린다.

상위 **3~4개 주제**를 고른다. 각 문단은 **그 주제에서 무엇이 가장 이슈가 된 포인트인지를
첫 문장에** 둔다.

### 4-1-1. 동명이인·무관 꼬리 가드 (필수)

인물명 단독 질의이므로 **동명이인·동명 일반어의 꼬리말이 섞인다.** 꼬리말 주제가 이 인물의
것인지 **네이버 인물DB·나무위키와 대조해 무관한 것은 버린다.** 버린 것도 §6 원본 기록에는
남긴다(선정이 자의적이지 않음을 사람이 확인해야 한다).

판정 도구 — 네이버 인물DB의 **"함께 출연한 다른 인물"** 섹션과 나무위키 필모그래피.
꼬리말의 인물명이 거기 있으면 이 인물의 것이다. 인물DB **"같은 이름 다른 인물"** 목록이 길면
(김지원은 22명) baseline 뉴스에 동명이인이 섞였다고 보고 전수 확인한다.

### 4-2. 자동완성은 선정 신호이고 근거가 아니다

자동완성 1위 주제라도 **`news` 등급(언론 2곳 이상) 또는 네이버 인물DB 근거가 없으면 쓰지
않는다.** 자동완성은 "무엇을 다룰지"를 정하고, 사실은 §1 우선순위가 정한다.

> **단, 근거가 없다는 판정을 §2-2 3회 검색으로 내리지 않는다.** v3 파일럿은 `얼굴`·`단발`
> 2슬롯을 "뉴스 2곳 근거 없음"으로 버렸는데, v4 확대 조사에서는 **같은 주제에 근거가 나왔다**
> (CBC뉴스 2026-09-16 단발 변신 반응 기사 + 태양의 후예 단발 경위 인터뷰). 외모·스타일 꼬리말은
> **변신·연기 변화의 입구**인 경우가 많다 — `<인물명> 단발`, `<인물명> 변신`으로 한 번 더 돈 뒤
> 버린다.

### 4-3. 쓸 수 있는 가십의 경계

- **배우자·가족이 공인(연예인·공개 활동)이면 쓴다.** 비공인 가족, 미성년 자녀, 일반인 지인은
  쓰지 않는다.
- 열애설·구설은 **`news` 2곳 이상** 필수.
- **열애·사생활 이슈는 3요소를 조사한다**(2026-10-17 이규한 피드백) — ① 왜 이슈가 됐나
  (나이 차, 만남 경위, 부인→인정 번복 같은 화제 포인트와 당시 반응) ② 이후 행보(공개 연애
  중의 동반 활동·발언) ③ 결말과 사유(결별 사유 — 공식 입장에 사유가 없으면 "밝혀진 사유
  없음"이라고 적는다). 인정·결별 날짜만 적은 조사는 집필에서 연표 문단밖에 못 만든다.

## 5-B. 소스풀 밖 참고자료 — AI 답변 (2026-10-17)

입력 프롬프트에 `## 네이버 AI 답변 (구조 참고 전용)` 또는 `## 구글 AI 답변 (구조 참고 전용)` 절이 있으면
검색 AI의 생성 답변이다. **§1 우선순위 표에 들지 않는다 — 소스풀 밖 참고자료다.** 어떤 축(드라마·영화·예능·광고)을
다루고 각 축의 대표를 무엇으로 뽑았는지만 **조사 커버리지 체크리스트**로 쓴다. 개별 사실(연도·작품명·수상)은 오류가
실측된 바 있어(데뷔를 1998년 '사랑과 성공'으로 답변 — 인물DB·나무위키는 1996년 '스타트') 인용하지 않는다. 인물DB·나무위키·
뉴스와 충돌하면 AI 답변을 버린다. 출처 목록(§10)에도 올리지 않는다.

## 6. 출력 파일 규격

`research/[인물명].md`.

### 6-0. 입력 계약

```yaml
keyword: 김지원              # 필수. 인물명. 임의로 다듬지 않는다
headline: 닥터X …            # 선택. 현재 화제작
background: …               # 선택. 핫스타 metadata.background
```

**`background`는 출력 §1(지금 화제인 이유)의 출발점이다.** 그대로 옮기지 않고, §2-1~2-8로
사실을 확인한 뒤 §1을 쓴다. `background`가 없으면 현재 화제작 보도로 대체한다.

### 6-1. frontmatter

**형식은 파서 계약이다**(IMPL §E-2). **중첩 구조와 키 이름을 바꾸지 않는다.**

```yaml
---
keyword: <인물명>
category: person
verdict: ok | thin | blocked
source_counts:
  official: N
  news: N
  community: N
sources_opened: 열어본 고정 출처 목록
researched_at: YYYY-MM-DD
---
```

#### verdict 판정식 (v4 재설계)

v3의 `official + news >= 5 -> ok`는 **화제작 요약 기준**이었고, 탐사식 조사량의 1/4이다.
v4는 **총량 + 커버리지 + 정성 재료**를 함께 본다.

| verdict | 조건 |
|---|---|
| **`ok`** | 아래 셋을 **전부** 충족 — ① `official` + `news` **12건 이상** ② **대표작 전부**에 리뷰성 출처(리뷰·평론·종영 기사·인터뷰) **1건 이상** ③ **정성 인용문(§3-1) 10건 이상** |
| **`thin`** | ①~③ 중 하나라도 미달. 단 `official` + `news`가 1건 이상 |
| **`blocked`** | `official` + `news`가 **0건** (v3 기준 유지) |

**근거 — 김지원 재조사 실측(2026-10-15)**

| 항목 | 실측 | 하한 설정과 이유 |
|---|---|---|
| `official` + `news` | **22건** (official 3 / news 19) | **12** = 실측의 약 55%. 재료가 얇은 인물에도 닿는 선이면서 v3(5건)의 2.4배 |
| 대표작별 리뷰성 출처 | 닥터X 5 / 눈물의 여왕 3 / 나의 해방일지 2 / 태양의 후예 2 / 쌈 마이웨이 2 — **전부 2건 이상** | **1건.** 작품 문단 하나에 평가 근거 하나는 최소선이고, 실측은 그 2배 이상 나왔다 |
| 정성 인용문 | **22건** | **10** = 실측의 약 45%. 섹션 10개 구조에서 섹션당 1개 |
| 검색·열기 횟수 | WebSearch 11 + WebFetch 21 + curl 4 = **36회** | §2-2 뉴스 8회 + §8 WebFetch 12건 |

**`blocked`의 실제 효과**: 현행 파이프라인은 verdict와 무관하게 진행한다
(`runResearchStageCli.ts` — ok/thin/blocked를 가리지 않고 자동 진행). `blocked`는 구흐름
알림에서 ✍️ 버튼이 빠지는 것뿐이다. **person 한정 `blocked` write 차단 게이트는 3단계
결정 사항**이다 — 인물 실명 글이라 자료 0건 자동 집필을 막을 필요가 있다.

### 6-2. 섹션

**섹션 번호가 v3에서 바뀌었다. 단 `## 10. 전체 출처 목록`의 헤더 문구 "전체 출처 목록"은
유지한다** — `parseResearchFile`이 헤더 텍스트로 이 표를 찾는다(발주 §2-2).

```
## 1. 지금 화제인 이유        <- "왜?"에 답한다. background 출발 + 복귀 맥락
## 2. 현재 작품과 배역        <- 배역명·중요도는 네이버 인물DB 기준. 캐릭터의 '정체' + 리뷰 인용
## 3. 작품별 카드             <- v4 신설. 대표작 3~5개, 작품당 블록 하나 (§2-6)
## 4. 정량 지표              <- 시청률·관객 수·순위·수상. 없으면 "없음"
## 5. 데뷔와 초기 활동        <- 캐스팅 경위·데뷔 CF·초기작. 연극/드라마/영화 구분
## 6. 사람 <이름>            <- v4 신설. 공개 신상 + 과거 일화·본인 발언 (§2-7)
## 7. 작품 외 최근 활동        <- 예능·광고·화보. "가장 이슈가 된 포인트" (§2-8)
## 8. 작품 외 활동 주제 선정    <- 자동완성 원본 + 주제 묶음 + 선정/버림 근거 (§4)
## 9. 자료 간 불일치          <- 네이버 인물DB를 기준으로 어느 출처가 다른지
## 9-1. 쓰지 않을 것          <- 제외 판정과 이유
## 10. 전체 출처 목록         <- 등급 표기. 헤더 문구 고정
```

**`## 3. 작품별 카드` 블록 형식**

```
### <작품명> (<방송사·배급>, <연도>) — <배역명> / <중요도>
- 캐릭터: …                      <- ① (인물DB 기준)
- 후킹 포인트: …                 <- ② 명장면·명대사·변신. 장면 단위로 특정
- 평가 근거: "<인용문 원문>" — <매체>, <URL>   <- ③ 최소 1건
- 정량: …                        <- 있으면. 없으면 줄을 뺀다
```

**`## 6. 사람 <이름>`에 들어갈 것**: 생년·출생지·학력·소속사(인물DB 기준) + §2-7에서 나온
과거 일화·본인 발언. **발언은 원문 + 출처 매체·시점을 그대로 적는다.**

**§10은 표로 쓰고 열 순서를 고정한다**(파서 `parseSourceTable` 계약). **이 순서를 바꾸지 않는다.**

```
| # | 등급 | 제목 | URL | 발행일 |
```

**§8에는 자동완성 결과 원본을 그대로 남긴다.** 선정이 자의적이지 않음을 사람이 확인할 수 있어야 한다.
