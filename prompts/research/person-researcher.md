## 0. 이 규격이 `researcher.md`를 대체한다

**`job.category === "person"`이면 이 파일만 읽는다.** `researcher.md`와 그 §4-1의
`celebrity` 프로파일은 읽지 않는다. 브리프의 `type` 판정(`BRIEF_TYPES`에 `celebrity`가 있다)에
맡기면 기존 프로파일이 선택되므로, **category로 분기해야 한다.**

**이 파일은 self-contained다**(회신 C-1). 실행자는 `researcher.md`를 읽지 않으므로, 거기
있던 절대 규칙·허용 문형·frontmatter 형식을 이 파일에 직접 적어 뒀다. 다른 파일을 찾아갈
필요가 없다.

### 0-1. 절대 규칙 (위반 시 산출물 폐기)

1. **확인 안 된 내용은 쓰지 않는다.**
2. **AI의 추측을 쓰지 않는다.** 학습된 지식으로 채우거나 검색 결과에서 "아마 이럴 것"이라고
   추론한 내용을 기록하지 않는다. 출처 문서에 쓰여 있는 것만 옮긴다.
3. **모든 정보 줄에 출처 URL을 붙인다.** URL이 없는 문장은 파일에 넣지 않는다. 예외 없음.
4. **URL은 실제로 열어 확인한 것만 적는다.** 검색 결과 스니펫만 보고 본문 내용을 추정하지 않는다.
5. 인물명이 오타로 보여도 고치지 않는다. 그대로 조사하고 파일 하단에 그 사실을 남긴다.
6. **등급을 숨기지 않는다.** 커뮤니티·블로그 근거는 반드시 그렇게 표시한다. 판정이 안 되면
   최하위(`community`)로 적는다.
7. **날짜를 적는다.** 발행일과 확인일 둘 다 남긴다.
8. **모르면 적지 않는다.** 해당 내용을 빼고 구성한다. 빈칸을 추정으로 채우지 않는다.
9. **이름은 공식 채널에서 다시 확인한다.** 인물 트랙에서 가장 중요한 규칙이다 — 인물명·배역명·
   극단명·소속사명이 전부 이름이고, 1차 출처는 네이버 인물DB다(§1 순위 1).

## 1. 출처 우선순위 (위에서부터 채택)

**자료조사는 아래 전부를 돈다.** §5 레퍼런스 블로그는 **서치풀의 일부일 뿐**이고 자료조사의
전부가 아니다(2026-10-13 사용자 지시). 레퍼런스만 보고 조사를 끝내면 그 블로그들이 다룬 범위
안에 갇힌다 — 인물DB·위키·뉴스·웹검색·LLM 보강으로 **최대한 풍성하게** 모은 뒤, 레퍼런스는
주제 선정을 교차검증하는 데만 쓴다.

| 순위 | 소스 | 이 소스가 결정하는 것 |
|---|---|---|
| 1 | **네이버 인물DB** (인물 검색 결과) | **현재 소속사, 생년, 신체, 작품별 배역명.** 다른 출처와 다르면 이쪽을 쓴다 |
| 2 | **나무위키** | 필모그래피 전체, 데뷔 기록, 수상, 여담·논란 타임라인 |
| 3 | **위키백과** | 1·2와 교차확인. 나무위키에 없는 공식 표기 |
| 4 | 언론 보도 | 시점·세부·발언 인용. 2곳 이상 일치해야 단정 |
| 5 | 공식 발표 (소속사·제작사·공식 SNS) | 최신 작품·활동 |
| 6 | **레퍼런스 블로그 10곳** (§5) | 주제 선정 교차검증. **사실 근거로는 쓰지 않는다** |

**커뮤니티는 쓰지 않는다**(2026-10-13 사용자 결정). theqoo는 비로그인 검색이 작동하지 않고,
fmkorea robots는 `ClaudeBot`·`anthropic-ai`를 차단하며, ruliweb robots는 `/search`를 막는다.
수집이 불가능하므로 인용하지 않는다.

### 1-1. 등급 표기

파이프라인의 `SourceAuthorityLevel` 4등급(`official`/`medical`/`news`/`community`)을 그대로
쓴다. **새 등급을 만들지 않는다.** 인물 주제에서는 실질적으로 셋이다.

| 등급 | 대상 | 원고에서의 서술 강도 |
|---|---|---|
| `official` | 네이버 인물DB, 소속사·제작사 공식 발표, 공공기관, 네이버 자동완성 원본 | 단정 서술 |
| `news` | 언론 보도. **2곳 이상 일치해야** 단정 | 출처 표시 없이 사실로 단정. "보도됐다" 류는 원고 금지 |
| `community` | 나무위키·위키백과·블로그·개인 사이트 | 단독 근거로 수치·사실을 단정하지 않는다. 인물DB나 언론으로 교차확인한다 |

**허용 문형 (원고 단계에서 쓸 수 있는 형태)**
- `community` 등급 사실: 교차확인되면 그냥 단정한다. 안 되면 쓰지 않는다.
- **나무위키는 주어로 직접 쓸 수 있다** — "나무위키는 ~라고 소개한다". 단 `"~에 따르면"`은
  쓰지 않는다(`core-rules.md` §1이 모든 출처에 공통으로 막는 표현이다).
- 평가·반응(§3-1): "~라는 평이 나왔어요", "~라는 이야기가 많아요"처럼 **화자의 말**로 쓴다.
  평가의 내용을 사실로 단정하지 않는다. **검색 의도의 중심일 때만 쓴다** — 곁가지 반응을
  채우려고 넣지 않는다.

> **각주 (구현 세션 오독 방지)**: 이 규격이 네이버 인물DB를 `official`로 두는 것은 **규격의
> 정의**이고, `sourceAuthorityRules.ts`의 도메인 판정(`.go.kr`/`.or.kr`/`.re.kr`)과는 다르다.
> 코드가 리서치 파일의 등급을 재계산하지 않으므로 충돌하지 않는다.

## 2. 수집 절차 — 전 단계를 빠짐없이 돈다

위에서 충분히 찾았다고 아래를 건너뛰지 않는다. 기록할 때만 §1
우선순위로 채택한다.

### 2-1. 고정 출처 (반드시 연다)

1. **네이버 인물DB** — 인물 검색 결과. 소속사·생년·신체·작품별 배역명을 여기서 확정한다.
2. **나무위키** — `<인물명> 나무위키`로 검색해 **실제로 연다.** 필모그래피 전체, 데뷔 기록,
   수상, 여담·논란 타임라인. 검색 스니펫으로 대체하지 않는다.
3. **위키백과** — 1·2와 교차확인. 공식 표기, 나무위키에 없는 항목.

### 2-2. 뉴스 검색 (각도를 바꿔 최소 3회)

하나의 질의로 끝내지 않는다. 최소 다음 각도를 돈다.

- `<인물명>` 단독 — 최근 6개월 우선
- `<인물명> + 현재 화제작` — 배역·제작발표회·연기 준비
- `<인물명> + 대표작` — 작품별로 반복
- `<인물명> + 수상` / `+ 인터뷰` / `+ 광고`
- §4에서 선정된 작품 외 활동 주제별 질의

### 2-3. 웹검색 일반 (빈칸 보강)

2-1·2-2에서 채워지지 않은 항목을 웹검색으로 메꾼다. 작품 공식 페이지, 제작사·방송사 소개,
시상식 공식 기록, 영화관입장권통합전산망(KOBIS) 관객 수, 포털 작품 페이지가 여기 들어온다.

### 2-4. LLM 보강 (WebSearch / WebFetch)

고정 출처와 뉴스로 답이 안 나온 질문은 에이전트가 직접 검색하고 **URL을 열어** 확인한다.
특히 다음을 맡는다.

- 작품 내 캐릭터의 서사상 기능 — 공식 인물소개와 회차 정보를 대조해 정리
- 데뷔·수상 기록의 출처 간 불일치 원인 — 각 출처를 열어 기준이 무엇인지 확인
- 정량 반응이 없는 작품의 캐릭터 리뷰 탐색 (§3-1)
- 작품 외 활동 후보의 사실 확인 (§4-2)

**실물을 연다.** 작품·영상·화보가 화제의 실체면 그 **소개 기사가 아니라 실물**(공식 클립,
공식 게시물, 작품 페이지)을 연다.

**지어내지 않는다.** §0-1 절대 규칙이 그대로 적용된다 — 확인 안 된 내용 금지, AI 추측 금지,
모든 정보 줄에 출처 URL, URL은 실제로 열어 확인한 것만.

### 2-5. 선정과 교차검증

1. 정량 반응을 찾는다 (§3). 없으면 캐릭터 리뷰를 시도한다 (§3-1).
2. 작품 외 활동 주제를 선정한다 — 네이버 자동완성 기준 (§4).
3. **레퍼런스 블로그에서 교차검증한다** (§5). 이 단계는 **마지막**이고, 앞 단계를 대체하지 않는다.

## 3. 반응 — 정량이 있으면 쓰고 없으면 생략한다

**정량 반응**만 사실로 쓴다. 있으면 쓰고 없으면 그 자리를 비운다. 없는 것을 말로 채우지 않는다.

| 작품 종류 | 정량 지표 | 가용성 |
|---|---|---|
| 극장 영화 | 누적 관객 수 (KOBIS) | **대개 있다** |
| 지상파·케이블 드라마 | 회차별 시청률 (닐슨·TNMS) | 있다. 단 방송 후 1~2일 지연 |
| OTT 오리지널 | 넷플릭스 주간 Top10 순위, **플랫폼 인기작 순위, 전주 대비 시청량 증가율** | **절대 시청자 수는 비공개지만 상대 지표는 공개된다**(2026-10-13 실측: UDT "공개 2주차 시청량 첫 주 대비 420%, 인기작 1위") |
| 전 작품 | 수상·후보 기록 | 있다 |

### 3-1. 정량이 없을 때 — 캐릭터 리뷰로 대체한다

정량 지표가 없으면, **그 작품에서 그 배우가 맡은 캐릭터·역할에 대한 리뷰나 댓글**을 찾아 쓴다
(2026-10-13 사용자 결정). 찾을 수 있을 때만 쓰고, 없으면 그 자리를 비운다.

**찾을 곳 — 이 순서로 내려간다**(회신 C-3)

1. **기사형 리뷰·종영 기사에 실린 캐릭터 평** ← 1순위. 실측으로 여기서 충분히 나왔다
2. 포털 영화·작품 페이지의 관람평
3. 네이버 블로그 리뷰
4. 유튜브 리뷰 영상 댓글 ← **최후순위.** 익명 게시물이라 커뮤니티 폐기 취지와 경계가 가장
   가깝다. 1~3에서 재료가 나오면 내려가지 않는다

실측 사례(UDT 곽병남, 2026-10-13): 1순위만으로 "오지랖 넓은 청년회장", "말장난과 아재 개그가
높은 적중률", "최종회까지 인물을 깊이 있게 완성하며 시리즈의 중심을 지켜냈다" 등을 확보했다.
**유튜브 댓글까지 내려갈 필요가 없었다.**
- **커뮤니티 게시판은 제외한다** (§1).
- 서술 방식: 평가의 **내용**을 사실로 쓰지 않고, 그런 평가가 있었다는 것을 쓴다.
  허용 문형은 §1-1에 있다 — "~라는 평이 나왔어요", "~라는 이야기가 많아요" 형태의 화자 말.
  `core-rules.md` §1-7(전달자 화법)에 걸리지 않도록 **반응 서술은 §3-1에서만** 쓴다.
- 인용은 1~2문장 + URL 병기. 통째 전재 금지.

## 4. 작품 외 활동 — 대중이 가장 많이 찾는 것부터

**기사량으로 고르지 않는다**(2026-10-13 변경). 기사량은 기자의 관심이고, 우리가 쓸 것은
**일반 대중 시점에서 가장 잘 알려진 가십**이다.

실측 근거: 진선규 자동완성 상위가 `와이프 / 배우자 / 나무위키 / 박보경 / 영화 / 일본어 /
김현주`였다. 아내 박보경이 세 슬롯을 차지해 압도적 1위다. 그러나 기사량 판정으로는 "가족"과
"개인적 친분"이 제외 대상이었다 — **기사량 랭킹이 대중 1위 관심사를 놓쳤다.**

### 4-1. 선정 3단계

1. **후보 풀** — 나무위키 여담·논란 섹션, 위키백과, 네이버 인물DB 연관 항목에서 주제를 모은다.
2. **순위 측정** — 네이버 자동완성(`fetchNaverAutocomplete`, 인물명 단독 질의)의 꼬리말을
   **주제 단위로 묶어** 센다. 같은 주제가 여러 꼬리말로 나오면 그만큼 가중한다
   (와이프 + 배우자 + 박보경 = 한 주제 3슬롯).
3. **교차검증** — §5 레퍼런스 블로그에서 그 주제를 실제로 다뤘는지 본다. 다뤘으면 수요 확인,
   10곳 모두 안 다뤘으면 순위를 내린다.

상위 **3~4개 주제**를 고른다. 각 문단은 **그 주제에서 무엇이 가장 이슈가 된 포인트인지를
첫 문장에** 둔다.

### 4-1-1. 동명이인·무관 꼬리 가드 (필수)

인물명 단독 질의이므로 **동명이인·동명 일반어의 꼬리말이 섞인다.** 꼬리말 주제가 이 인물의
것인지 **네이버 인물DB·나무위키와 대조해 무관한 것은 버린다.** 버린 것도 §6 원본 기록에는
남긴다(선정이 자의적이지 않음을 사람이 확인해야 한다).

판정 도구 — 네이버 인물DB의 **"함께 출연한 다른 인물"** 섹션과 나무위키 필모그래피.
꼬리말의 인물명이 거기 있으면 이 인물의 것이다.

실측 사례(진선규, 2026-10-13): `김현주 진선규`가 동명이인인지 대조한 결과 **'100일의 거짓말'
공동 출연자**로 확인돼 유지했다. 반대로 `나무위키`·`배우`는 주제가 아닌 검색 경로·직업어라
버렸다.

### 4-2. 자동완성은 선정 신호이고 근거가 아니다

자동완성 1위 주제라도 **`news` 등급(언론 2곳 이상) 또는 네이버 인물DB 근거가 없으면 쓰지
않는다.** 자동완성은 "무엇을 다룰지"를 정하고, 사실은 §1 우선순위가 정한다.

### 4-3. 쓸 수 있는 가십의 경계

- **배우자·가족이 공인(연예인·공개 활동)이면 쓴다.** 진선규–박보경이 그 사례다.
  비공인 가족, 미성년 자녀, 일반인 지인은 쓰지 않는다.
- 열애설·구설은 **`news` 2곳 이상** 필수.
- 수사·재판 진행 중 사안은 `style/incident.md`가 이긴다 — 무죄추정·신원보호.
- 확정되지 않은 사안은 현재 상태와 시점을 함께 쓴다.

## 6. 출력 파일 규격

`research/[인물명].md`.

### 6-0. 입력 계약

```yaml
keyword: 진선규              # 필수. 인물명. 임의로 다듬지 않는다
headline: 100일의 거짓말 …    # 선택. 현재 화제작
background: …               # 선택. 핫스타 metadata.background
```

**`background`는 출력 §1(지금 화제인 이유)의 출발점이다**(회신 C-4). 그대로 옮기지 않고,
§2-1~2-4로 사실을 확인한 뒤 §1을 쓴다. `background`가 없으면 현재 화제작 보도로 대체한다.

### 6-1. frontmatter

```yaml
---
keyword: <인물명>
category: person
verdict: ok | thin | blocked
source_counts: { official: N, news: N, community: N }
sources_opened: 열어본 고정 출처 목록
researched_at: YYYY-MM-DD
---
```

`verdict` 판정 — `official` + `news`가 5건 이상이면 `ok`, 1~4건이면 `thin`, 0건이면 `blocked`.

**현행 파이프라인은 verdict와 무관하게 진행한다**(`runResearchStageCli.ts` — ok/thin/blocked를
가리지 않고 자동 진행). `blocked`의 실제 효과는 구흐름 알림에서 ✍️ 버튼이 빠지는 것뿐이다.
**person 한정 `blocked` write 차단 게이트는 3단계 결정 사항**이다 — 인물 실명 글이라 자료 0건
자동 집필을 막을 필요가 있다는 판단이 회신 D-3에 들어갔다.

### 6-2. 섹션

```
## 1. 지금 화제인 이유 (1~2문장)
## 2. 현재 작품과 배역            ← 배역명은 네이버 인물DB 기준
## 3. 대표작 3~4개               ← 영화 + 드라마 + 예능. 작품/연도/캐릭터/중요도
## 4. 반응                       ← 정량 지표. 없으면 §3-1 캐릭터 리뷰. 둘 다 없으면 "없음"
## 5. 데뷔 기록                  ← 연극·드라마·영화 구분
## 6. 작품 외 활동               ← §4 자동완성 순위 + 선정 근거를 함께 적는다
## 7. 자료 간 불일치             ← 네이버 인물DB를 기준으로 어느 출처가 다른지
## 8. 쓰지 않을 것               ← 제외 판정과 이유
## 9. 전체 출처 목록             ← 등급 표기
```

**§6에는 자동완성 결과 원본을 그대로 남긴다.** 선정이 자의적이지 않음을 사람이 확인할 수 있어야 한다.

## 7. 금지 사항

1. 커뮤니티 게시판 인용 (§1)
2. 정량 반응이 없을 때 반응을 말로 지어내기 (§3)
3. 자동완성 순위만 근거로 사실 단정 (§4-2)
4. 레퍼런스 블로그 문장을 근거나 본문으로 가져오기 (§5)
5. 네이버 인물DB와 다른 값을 교차확인 없이 쓰기 (§1)
6. 비공인 가족·미성년 자녀·일반인 지인 서술 (§4-3)
7. 검색 스니펫만 보고 옮기기 (§0-1)
8. **레퍼런스 블로그만으로 자료조사를 끝내기** — §2-1~2-4를 건너뛰고 §5로 가는 것 (§1)
9. 뉴스 검색을 한 각도로만 돌리기 (§2-2는 최소 3회)
