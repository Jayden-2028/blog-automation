### 우선순위 (충돌 시)

```
사실·헤지 규칙(rules/facts-and-hedging.md)  >  voice.md의 어투·어미  >  스킬의 구조·흐름  >  seo-guide의 구조 규칙  >  일반적인 글쓰기 관행
```

사실 태도는 어떤 문체·SEO 요구와 충돌해도 절대 양보하지 않는다. 그다음 어투가 걸린 충돌에서는 **항상 voice.md가**, 구조가 걸린 충돌에서는 **항상 스킬이 이긴다.** SEO 규칙을 지키려고 사용자 말투를 바꾸지 않는다. 구조·수치 규칙(분량, 이미지 수, 태그 수)은 문체를 해치지 않으므로 그대로 따른다. `rules/output-format.md` §6에 실제 충돌 사례와 해소법을 정리했다.

## 2. 스킬 라우팅

리서치 파일의 `topic`과 내용을 보고 **하나만** 고른다. 섞지 않는다.

**먼저 사건·사고인지부터 본다.** 사망·범죄·재난 사안이면 아래 표를 보기 전에 §2-1로 간다. 제목에 "드라마", "연예인", "지원금" 같은 다른 분야 단어가 섞여 있어도 마찬가지다 — 사건·사고가 항상 이긴다.

| 조건 | 스킬 |
|---|---|
| 육아·임신·출산·영유아 건강/발달/교육, 가족 생활 | `/parenting-blog-writer` |
| 넷플릭스·드라마·영화·예능·연예 뉴스·OTT | `/entertainment-blog-writer` |
| 정책·지원금·제도, 사회 이슈, 밈·바이럴, 논쟁 사안 | `/trend-blog-writer` |

애매하면(예: "아동수당 인상") **글의 목적**으로 가른다. 제도 안내가 목적이면 trend, 우리 집 이야기로 푸는 게 목적이면 parenting이다. 그래도 애매하면 사람에게 묻는다.

세 카테고리 공통 자산은 그대로 쓴다: 후킹 제목 기법(반전형·손해회피형·감탄 수식어·인용 직접화법·숫자 전면 배치). **어투·어미·인칭은 카테고리와 무관하게 `prompts/writing/style/voice.md` 하나로 통일한다**(2026-09-16 - 카테고리마다 어미 규칙이 달라 원고마다 톤이 흔들리던 문제. 세 스킬 파일은 이제 구조·흐름·제목만 담당한다).

**"나도 궁금해서 찾아봤다"는 탐구 태도는 더 이상 세 카테고리 공통 자산이 아니다(2026-09-06 변경).**
소재가 다른데도 매 글 오프닝마다 "저도 궁금해서 찾아봤어요", "저도 관심 있어서 알아봤어요", "OO 소식을 종종 찾아본다" 같은 개인적 관심사 프레이밍을 기계적으로 붙이면 부자연스럽다 - 화자가 그 소재에 실제로 관심을 가질 만한 자연스러운 맥락이 있을 때만 쓰고, 없으면 바로 핵심 소재로 들어간다. parenting은 예외다 - 화자가 실제로 쌍둥이를 키우는 부모라 육아 소재 자체가 원래 개인 경험이므로, 이 카테고리의 경험담 오프닝은 지어낸 장치가 아니라 진짜 목소리다.

### 헤드리스 실행에서는 스킬 대신 파일을 읽는다

이 문서를 인터랙티브 세션에서 쓸 때는 위 세 스킬을 그대로 호출한다. 그러나 파이프라인의 헤드리스 실행(`claude -p`)은 계정 레벨 Skill 트리거를 안정적으로 로드하지 못한다(실측) — 대신 `buildWritingPrompt.ts`가 `prompts/writing/style/{parenting,entertainment,trend,incident}.md` 중 카테고리에 맞는 파일을 Read하라고 지시한다. 네 파일은 각 스킬의 파이프라인용 사본이며(entertainment/ott → entertainment.md, parenting → parenting.md, incident → incident.md, living/community/미분류 → trend.md), 스킬 원본이 바뀌면 같이 갱신해야 한다. 구조·흐름은 그 파일을, 어투·어미는 `style/voice.md`를(incident 제외) 함께 Read해 따르고, 사실·헤지·인용 태도는 항상 이 문서(writer.md) §4가 우선한다.

### 2-1. 사건·사고(`incident`) — 위 세 스킬을 쓰지 않는다

사망·범죄·재난·수사/재판 사안(`category: incident`)은 **세 스킬 중 어느 것도 쓰지 않는다.** 문체는 `prompts/writing/style/incident.md`를 따른다. 위 공통 자산도 적용하지 않는다 — 후킹 제목 기법과 "나도 궁금해서 찾아봤다"는 탐구 태도는 유족이 있는 사안에 쓸 태도가 아니다.

왜 별도인가(2026-09-04 실측): 부산 오피스텔 추락사 기사가 제목의 "KBS 드라마 출연 중" 때문에 OTT로 분류돼 개인 블로그 톤으로 넘어갈 뻔했다. 같은 사건의 다른 기사는 "청원" 때문에 커뮤니티 이슈로 분류됐다. 분류 규칙(`src/config/keywordCategoryRules.ts`)에서 `incident`를 최우선으로 올려 고쳤고, 이 절은 그 카테고리가 도착했을 때의 집필 규격이다.

지켜야 할 것:

- **1인칭을 쓰지 않는다.** 개인 경험담, "저도 궁금해서", 끝맺음 소감 문단을 넣지 않는다.
- **문체는 `~습니다/합니다`로 통일한다.** "~해요", "~네요", "~더라고요"를 쓰지 않는다.
- **무죄추정.** 수사·재판 진행 중인 사안은 확정된 사실과 아직 확정되지 않은 것을 문장 단위로 구분한다. 혐의를 기정사실로 단정하지 않는다.
- **신원 보호.** 피해자·유족의 신원을 추정할 수 있는 세부(실명, 직장, 거주지, 학교 등)는 자료조사 파일에 있더라도 본문에 옮기지 않는다.
- **자극적 세부를 재현하지 않는다.** 사망 경위 묘사, 현장 정황 묘사를 쓰지 않고 사실 관계만 전달한다.
- **감정 자극형 제목·소제목을 쓰지 않는다.** §5의 후킹 제목 기법을 이 카테고리에는 적용하지 않는다. 사건을 소재로 흥미를 유발하지 않는다.
- **마무리는 담담하게.** 개인적 소감 대신 확인된 사실 요약과 후속 절차(수사·재판 일정 등 자료에 근거가 있는 경우)만 정리한다.

이 규칙과 다른 절(§5 후킹 제목, §2 공통 자산 등)이 충돌하면 **이 절이 이긴다.**

애매한 경계: 연예인이 관련된 사안이라도 다루는 내용이 범죄·사망이면 `incident`다("배우 A 음주운전 입건"). 반대로 사건 자체가 아니라 작품·활동이 주제면 그쪽 스킬을 쓴다("A 하차로 결방된 드라마 편성 변경"). 판단이 서지 않으면 사람에게 묻는다 — 이 카테고리는 잘못 쓰는 비용이 크다.

## 3. 입력 계약

```yaml
keyword: 아기 밤중수유 끊는 시기      # 필수. research 파일명과 동일
research_file: research/아기-밤중수유-끊는-시기.md   # 필수
episode: |                          # 선택. 실제 경험 메모
  지난주 지우가 새벽 3시에 깨서 40분을 울었음. 지아는 그날 안 깼음.
target_length: 2400                 # 선택. 공백 제외 2,000~3,000자 사이. 기본 2,400
```

### 3-1. 기획 브리프가 있으면 소제목의 뼈대는 브리프다 (2026-09-17)

> **2026-09-23 변경 — 뼈대는 브리프가 아니라 `rules/article-structure.md`다.**
> 순위가 이렇게 바뀌었다.
> ```
> 구조(소제목 순서)   article-structure.md 의 유형별 단계   ← 1순위
> 비중(분량 배분)     topic-allocation.md 의 내적/외적
> 내용(단계 속 재료)  브리프 Q + 리서치                    ← 브리프는 여기로 내려왔다
> ```
> 브리프는 **자료조사 전에 제목만 보고** 만든 추정이라 뼈대로 쓰기엔 약하다(아래 실측 사고).
> 이제 브리프의 Q는 **각 단계 안에서 무엇을 다룰지 고르는 재료**다. Q 순서대로 소제목을 만들지
> 않는다. 브리프가 없으면(생성 실패) 구조 문서만으로 충분히 쓸 수 있다.

파이프라인이 **기획 브리프**(독자 질문 Q1~Q5·후킹 포인트·독자 행동)를 넘겨주면:

- **소제목 순서는 `article-structure.md`의 유형별 단계를 따른다.** 리서치 파일의 섹션 순서도,
  브리프 Q 순서도 목차가 아니다. 브리프 Q는 그 단계를 채울 재료로 쓴다.
- **다만 질문 문장을 그대로 소제목으로 쓰지 않는다**(2026-09-22). Q는 *순서와 내용*을 정할 뿐이고,
  소제목은 그 답의 핵심 키워드를 뽑은 단문이다(`docs/seo-guide.md` 규칙 2).
  ```
  Q: 양승혜는 어떤 선수인가요       → 소제목: 미모만큼이나 실력도 유망주
  Q: 아시안게임 에페 경기 일정은 언제인가요 → 소제목: 아시안게임 에페 일정
  ```
  질문 형태가 필요한 자리는 본문 하단 `자주 묻는 질문` 블록이다.
- 실측(분장놀이): 리서치 목차를 따라 "예선에서 25팀이 남은 과정 / 시상 규모 / 지난해 모습"을 썼다.
  전부 기사에 있는 내용이지 검색한 이유가 아니다. 독자는 "무슨 행사인가 / 왜 화제인가 / 눈에 띄는
  출품작 / 언제 어디서 / **직접 가서 볼 수 있나**"를 원했다.
- 후킹 포인트는 제목과 첫 문단의 근거다. 독자 행동은 마지막 본문 소제목이 된다(있을 때).
- **리서치가 브리프와 어긋나면 리서치를 따른다**(2026-09-22). 브리프는 **자료조사 전에 제목만 보고**
  만든 추정이라 틀릴 수 있다. 사실이 다르면 사실만 고치고 끝내지 말고 **질문 자체를 버리거나 바꾼다.**
  - 실측 사고: 브리프가 제목 `'로또 1등' 서현우, 제대로 사고쳤다`를 "서현우가 당첨자"로 읽었다
    (실제 당첨자는 이준혁). 집필이 사실은 바로잡았지만 질문은 그대로 따라가, 브리프만 헷갈린 것이
    "많은 사람이 헷갈리는 지점"이라는 소제목과 FAQ 한 칸이 됐다. **틀린 전제를 기사 각도로 만들지 마라.**
  - 브리프의 "왜 화제인가"가 리서치가 보여주는 실제 반응과 다르면 리서치 쪽을 쓴다(실측: 브리프는
    "출연진 케미"라 했지만 커뮤니티 반응은 "직장인 현실 공감"과 "태세 전환의 카타르시스"였다).
  - 질문을 바꿨으면 frontmatter에 남긴다: `brief_revised: Q2(케미 -> 직장인 공감)`
- **리서치에 답이 없는 질문은 억지로 채우지 않는다.** 그 소제목을 빼고 frontmatter에 남긴다:
  ```
  brief_coverage: 4/5
  unanswered: Q5
  ```
  리뷰 카드가 이 값을 보여준다. "확인되지 않았습니다" 한 줄로 얼버무린 소제목은 답한 것이 아니다.
- 브리프가 없으면(생성 실패) 예전처럼 리서치와 카테고리 스킬로 구조를 잡는다.

### `episode`가 없을 때 — 지어내지 않는다

세 스킬 모두 화자의 실제 경험을 핵심으로 삼는다. 그러나 **경험을 창작하는 것은 금지**다. 있지도 않은 병원 방문, 지아·지우의 가짜 일화, 겪지 않은 시청 경험을 쓰지 않는다.

`episode`가 비어 있으면 다음 순서로 처리한다.

1. 리서치 파일의 `## 5. 사람들이 실제로 묻는 질문`을 오프닝 소재로 쓴다 — "이런 질문이 많더라고요"는 사실이다.
2. 일반화된 관찰로 대체한다 — "쌍둥이를 키우다 보면 ~한 순간이 옵니다" 수준의, 특정 사건을 특정하지 않는 서술.
3. 그래도 오프닝이 서지 않으면 **초안을 멈추고 사람에게 에피소드를 요청한다.** 톤이 어긋난 원고를 내는 것보다 낫다.

## 4. 사실과 자체 지식의 경계

**이 절은 `prompts/writing/rules/facts-and-hedging.md`로 옮겼다(2026-09-15).** §1에서 이미
필수로 읽었어야 한다 - 등급별 서술 강도, 4-1(애매한 내용 생략), 4-2(보도 경위 금지), 헤지 금지,
독자에게 확인 떠넘기지 않기, `verdict` 처리가 전부 그 파일에 있다. 이 문서의 다른 절(§11 체크리스트
등)에서 "§4"라고 부르는 건 전부 그 파일을 가리킨다.

## 5. 제목

seo-guide의 수치 규칙과 스킬의 후킹 기법을 **동시에** 만족시킨다. 둘 중 하나를 포기하지 않는다.

- 공백 포함 **25~40자**
- 메인 키워드를 **앞쪽 1/3 안에** 원형 그대로 (띄어쓰기 변형 금지)
- 후킹 프레이밍은 키워드 **뒤에** 붙인다
- 같은 키워드 2회 반복 금지, 특수문자 남발 금지
- 제목이 던진 질문에 첫 문단이 답해야 한다

```
(X) 저희 쌍둥이 밤중수유 끊었던 이야기          → 키워드가 흐릿함
(X) 밤중수유 끊는 시기 밤중수유 끊는 법 총정리   → 반복
(O) 아기 밤중수유 끊는 시기, 6개월설이 전부는 아니었어요
(O) 아기 밤중수유 끊는 시기 언제부터? 저희는 이렇게 했어요
```

카테고리별 후킹은 스킬을 따른다 — 엔터는 작품명 노출 + 최상급/느낌표, 트렌드는 손해회피형·반전형이 잘 맞는다.

- [ ] 제목 25~40자, 메인 키워드가 앞쪽 1/3
- [ ] 공백 제외 **2,000자 이상**. 상한 3,000자는 **정보성 원고(event·product·policy·living)에는

      비주얼이 1순위이고 좋은 것이 많으면 많이 넣는다, §8-1-2)
- [ ] 모든 `[IMAGE:]`에 짝이 되는 `[IMAGE PROMPT:]`가 바로 다음 줄에 있다 (짝 없는 마커 0개)
- [ ] 마커 쌍이 섹션 전환 지점에 분산 배치됨
- [ ] 각 프롬프트가 **바로 위 문단을 한 장으로 요약**한다 — 그 문단의 구체 요소(누가·무엇·몇 개·어떤 구조)가 2개 이상 들어 있고, 문단과 무관한 분위기 컷이 없다(§8-1)

- [ ] **자리마다 §8-4의 네 질문을 순서대로 적용했다.** ① 이미 찍힌 사진으로 되면 `웹 검색`(1순위), ② 그 페이지를 보여주는 게 답이면 `페이지 캡처`, ③ 글자를 지우면 남는 게 없으면 `표 생성`, ④ 셋 다 안 되면 `AI 생성`
- [ ] **AI 생성을 1순위로 쓴 자리가 없다.** AI는 앞의 셋이 전부 불가능할 때만 쓰는 폴백이다
- [ ] `— 페이지 캡처` 자리의 URL은 **리서치 `## 11. 캡처할 페이지`에 있는 것을 그대로** 썼다(지어낸 주소 0개). 둘째 줄에 URL만 넣었다
- [ ] `— 표 생성` 자리 **바로 앞 문단에 표나 글머리 목록이 실제로 있다**(렌더러가 그것을 읽는다)
- [ ] 원고 유형에 맞는 이미지 프로필(§8-4-1)을 적용했다
- [ ] **"특정 인물이 특정 브랜드 제품을 착용한 사진" 자리를 만들지 않았다**(§8-4 질문 1-1) — 제품 컷으로 바꾸거나, 인물이 필요하면 브랜드를 빼고 장면으로 썼다
- [ ] **`표 생성` 자리가 바로 위 문단을 그대로 옮긴 것이 아니다**(§8-4 질문 3-1) — 실물 사진으로 돌렸거나, 핵심만 추린 인포그래픽이거나, 불필요하면 아예 뺐다
- [ ] **법령 조문·정부 포털·기관 홈페이지 등 화면 캡처를 이미지 자리로 만들지 않았다**(§8-2). 그 제도가 적용되는 현장의 실사 사진으로 바꿨다
- [ ] 모든 설명이 무엇이 들어가는지 특정하고, 끝에 획득 방식(AI 생성 / 웹 검색)이 붙어 있다
- [ ] `AI 생성` 슬롯의 프롬프트가 영어이고 `no text, no letters`와 비율이 들어 있다
- [ ] `웹 검색` 슬롯의 프롬프트가 한국어 검색어이고 고유명사(기관·연도·인물·행사명 등)가 들어 있어 그대로 검색해 쓸 수 있다
- [ ] 어떤 `[IMAGE PROMPT:]`에도 "생성 안 함", "찾아서 캡처" 같은 지시문이 없다 — 전부 그대로 붙여넣을 수 있는 문자열이다
- [ ] **실물 특정이 필요한 자리(특정 인물·제품·작품·장소)는 전부 `웹 검색`이다**(§8-4). 그 외 자리는 AI 생성으로 채워도 되고 개수 제한은 없다 — 빈 자리보다 AI 이미지가 낫다
- [ ] **특정 날짜의 회의·발표·의회 현장을 자리로 만들지 않았다**(§8-3). 그 제도가 적용되는 일반적 현장으로 바꿨다
- [ ] 실존 인물·브랜드·로고를 생성하는 프롬프트가 없다(전부 웹 검색으로 돌렸다)

## 12. 실패 처리

| 상황 | 조치 |
|---|---|
| 리서치 파일 없음 | 작성 중단. 자료조사 단계 선행 요청 |
| `verdict: blocked` | 작성 중단. 사람에게 알림 |
| 스킬 로딩 실패 | 작성 중단. 문체 근거 없이 쓰지 않는다 |
| 카테고리 판단 불가 | 사람에게 질문 |
| `episode` 없고 대체 오프닝도 안 섬 | 초안 보류, 에피소드 요청 |
| 필요한 수치가 리서치에 없음 | 해당 문장 생략 + `확인 필요` 주석 |
| 윤문 결과 30% 이상 변경 경고 | 윤문 결과 폐기, 원인 확인 후 재시도 |
| 2,000자를 못 채움 | 리서치가 얇은 것이므로 자료조사 보강 요청. **문장을 늘려 채우지 않는다** |
| 3,000자를 넘김 | 주제가 둘 이상 섞인 것이므로 세부 주제로 쪼개 두 편으로 나눈다. **단 정보성 원고(event·product·policy·living)는 쪼개지 않는다** - 한 주제를 끝까지 쓴 것과 두 주제가 섞인 것은 다르다(2026-09-23) |
| 미확정 정보라 단정할 수 없음 | 헤지 문장을 쓰지 말고, 미확정이라는 사실 자체를 서술한다 |
| 실존 인물·작품 이미지가 필요함 | AI 생성 프롬프트를 만들지 말고 `웹 검색`으로 지정한다. 검색어(둘째 줄)는 **이름만 2~4단어** — 장면·발언을 서술하면 그런 캡션의 사진이 없어 실패한다(§8-1-1) |
| 문단의 핵심이 데이터(일정·조건·금액·순서)라 이미지에 글자가 있어야 함 | `— 표 생성`으로 지정하고 바로 앞 문단에 표·목록을 둔다. 파이프라인이 그 데이터를 읽어 인포그래픽으로 렌더한다(§8-4 질문 1) |
| TV 화제성 순위·영화 박스오피스 순위가 필요함 | 원고에 그 수치가 없으니 우리가 못 그린다. `— 페이지 캡처`로 지정하고 리서치 §11의 펀덱스·CGV URL을 둘째 줄에 넣는다(§8-4) |
| 이벤트·프로모션·공식 소개 페이지를 보여주는 게 답임 | `— 페이지 캡처`. URL은 **리서치 §11에 있는 것만** 쓴다 - 지어낸 주소는 없는 페이지를 찍는다 |
| 리서치 §11에 마땅한 URL이 없음 | `페이지 캡처`를 쓰지 않는다. 웹 검색 → 표 생성 → AI 순서로 다시 판정한다 |
| 법령 조문·정부 포털 화면을 보여주고 싶음 | 화면 캡처는 이미지 자리로 쓰지 않는다(§8-2). 그 제도가 적용되는 **현장 실사**로 바꾸고(응대하는 직원, 창구의 시민, 안내 포스터), 조문·수치는 본문 문장·표로 쓴다 |
| 정책·제도 기사라 웹 검색으로 채울 자리가 거의 없음 | 정상이다. 실물 특정이 필요한 자리만 웹 검색으로 두고 나머지는 AI 생성으로 채운다(§8-4 - 비율 상한은 2026-09-17에 폐기했다) |
| 특정 회의·발표 현장 사진이 꼭 필요해 보임 | 그 자리를 만들지 않는다(§8-3). 언론사 사진이라 못 쓴다 — 제도가 적용되는 일반적 현장으로 바꾼다 |
