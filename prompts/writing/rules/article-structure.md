# 카테고리별 초안 구조와 문단 흐름

> 위치: `prompts/writing/rules/article-structure.md` · 기준일: 2026-09-23 (사용자 제공 문서 + 보강 5건 확정)
> **소제목의 뼈대는 이 문서다.** `rules/topic-allocation.md`(무엇에 분량을 쓰나)와 짝이다 —
> 이쪽이 **순서**, 저쪽이 **비중**을 정한다. 두 모드(spec·auto) 공통이다.

---

## 0. 어느 흐름을 쓰나

기획 브리프의 `type`으로 고른다. 브리프가 없으면 `category`로 고른다.

| 흐름 | `brief.type` | `category` | 비고 |
|---|---|---|---|
| §1 작품 | `drama` | entertainment · ott | 드라마·영화·시리즈·예능·방송·광고필름 |
| §2 인물 | `celebrity` | entertainment | 연예인·스타·유명인 |
| §3 행사 | `event` | living · community | 행사·이벤트·공연·전시 |
| §4 제품 | `product` | living | 제품·서비스·할인·프로모션 |
| §5 사회 이슈 | `other` | community · living | **사건·사고는 여기가 아니다 → §8** |
| §6 정책 | `policy` | living | 정책·지원금·제도 |
| §7 육아 | — | parenting | 화자의 실제 경험이 중심 |
| §8 사건·사고 | `incident` | incident | **별도 규격. 이 문서를 쓰지 않는다** |

**섞지 않는다. 하나만 고른다.** 애매하면 글의 목적으로 가른다.

### 공통 규칙

- **각 단계가 소제목 하나일 필요는 없다.** 재료가 얇으면 두 단계를 한 소제목에 합치고, 두꺼우면
  한 단계를 두 소제목으로 쪼갠다. 지켜야 하는 것은 **순서**다.
- **마지막 `요약`은 소제목을 달지 않는다.** 제목 없는 마무리 문단으로 쓴다(`output-format.md` §7 —
  "결론", "마무리하며" 같은 소제목은 금지). 앞 문단에 이미 쓴 문장을 다시 쓰지 않는다.
- 재료가 없어 채울 수 없는 단계는 **건너뛴다.** "확인되지 않았습니다"로 칸을 채우지 않는다
  (`topic-allocation.md` §3).

## 1. 작품 — 드라마·영화·시리즈·예능·방송·광고필름

```
1. 개괄        어떤 작품인가 / 메인 캐스팅이 누구인가(이름만) / 언제 공개·개봉인가(대략)
2. 왜 화제인가  예매 오픈 · 캐스팅 소식 · 출연진 발언 · 홍보 콘텐츠 출연 · 감독의 발언
3. 주요 내용    시놉시스·스토리·알려진 줄거리 요약 / 대중이 언급하는 캐릭터·캐스팅 지점
4. 왜 반응하나  어떤 반응이 올라오나(공감·긍정·부정·재밌다·웃기다) / 공감 포인트 / 호평 지점 / 혹평 지점
5. 어디서 보나  방송이면 채널·방영일·주 몇 회 / OTT면 채널·공개일·몇 부작 / 영화면 개봉일·예매 오픈
6. 요약
```

- **1의 "메인 캐스팅"은 이름만 한 줄이다**(2026-09-23 확정). 프로필·전작·최근 활동은 여기가 아니라
  뒤쪽이고, 분량도 각 한 문단이다(`topic-allocation.md` §2). 앞에서 배우 소개를 시작하면 글의
  중심이 작품에서 사람으로 옮겨간다 — 실측 사고가 그것이다.
- **3과 4가 이 글의 중심이다**(내적 60%). 1·2·5는 각각 짧게 끝낸다.
- 3은 **작품·게시물 원문을 직접 열어** 쓴다(`researcher.md` §2-1). 기사 요약으로 대신하지 않는다.
- **출연자가 둘 이상이면 전원**을 다룬다. 한 명만 쓰고 넘어가지 않는다.

## 2. 인물 — 연예인·스타·유명인

```
1. 화제 상황 개괄  커뮤니티에서 회자 / SNS 반응 / 뉴스가 쏟아짐 / 팬들의 반응
2. 무엇을 했나     ★가장 중요★  어떤 사진(화보·SNS 공개) / 어떤 발언 / 어떤 행위
3. 그 배경         어떤 행사에서 / 어떤 이벤트에 나가서 / 어떤 방송에 출연해서
4. 대중의 반응     공감 · 긍정 · 부정 · 논란 · 찬반 · 기타
5. 요약
```

- **2가 이 글의 심장이다.** 여기에 가장 많은 분량을 쓴다. 나머지는 2를 이해시키기 위한 것이다.
- 3(배경)은 **2를 설명하는 데 필요한 만큼만**이다. 행사 자체를 소개하는 글이 아니다.
- 인물의 프로필·전작은 이 흐름에 **단계가 없다.** 독자가 그 인물을 모를 때만 짧게 넣는다 —
  이미 유명한 인물이면 "이 사람이 누구인가"에 칸을 쓰지 않는다.

## 3. 행사·이벤트

```
1. 개괄       어떤 행사가 뉴스가 되고 있나
2. 구체적 내용  무엇을 하는 행사인가 / 핵심 가치는 무엇인가 / 독자가 알 수 있는 정보는 무엇인가
3. 행사 정보   언제·어느 기간 / 어디서 / 온라인으로는 어디서 보나
4. 참여 방법   예매처·구입처 / 구입 방법 자세히 / 자격 요건 / 참여·예매 일정
5. 요약
```

- **2와 4가 중심이다.** 특히 4는 "자세히"가 규칙이다 — 어디서, 어떻게, 얼마에, 언제까지를
  문장으로 푼다. 목록 한 줄로 끝내지 않는다.
- **참여 업체·브랜드·혜택 금액은 2에 들어간다.** "여섯 개 분야 부스가 있었다"는 정보가 아니다.
  어떤 업체가 왔고 무슨 혜택을 걸었는지가 정보다(실측 사고, 2026-09-23 영등포).
- 이 유형은 **분량 상한을 적용하지 않는다**(`output-format.md` 충돌 5).

## 4. 제품·서비스·할인 (2026-09-23 신설)

```
1. 개괄       무슨 제품·서비스가 화제인가
2. 구체적 내용  무엇인가 / 가격 / 어떤 점이 좋고 나쁜가
3. 후기·반응   실제로 써 본 사람들이 뭐라 하나
4. 사는 방법   어디서 / 언제까지 / 조건·쿠폰 / 비교 대상
5. 요약
```

- **§3 행사와 헷갈리지 마라.** 행사는 "가면 뭘 볼 수 있나"가 중심이고, 제품은 **"샀더니 어땠나"**가
  중심이다. 그래서 이 흐름에만 3(후기·반응)이 있다.
- **2에 단점도 쓴다.** 장점만 쓰면 광고다. 후기에 나온 불만을 빼지 않는다.
- 가격은 **기준 시점을 그 값에 붙여** 단정한다("9월 23일 기준 12,900원").
- 이 유형은 **분량 상한을 적용하지 않는다**.

## 5. 사회 일반 이슈

```
1. 개괄       무슨 일이 있었나 / 어디서 발생했나 / 어디서 회자되었나
2. 발생 이유   사건의 발단 / 이슈가 어떻게 전개되었나 / 결과
3. 파장       어떤 결과가 나왔나 / 독자에게는 어떤 결과인가 / 알아야 할 정보·주의점
4. 대중의 반응  공감 · 긍정 · 부정 · 논란 · 찬반 · 기타
5. 요약
```

- **사망·범죄·재난이면 이 흐름을 쓰지 않는다.** §8로 간다. 유족이 있는 사안에 "어떤 반응이
  올라오나(재밌다·웃기다)"를 적용하면 안 된다.
- 3의 "독자에게는 어떤 결과인가"가 이 유형의 차별점이다. 남의 일로 끝내지 않는다.
- 찬반이 갈리는 사안은 **양쪽 논거를 모두** 쓴다(`researcher.md` §6).

## 6. 정책·지원금·제도

```
1. 개괄       무슨 정책인가
2. 구체적 내용  무엇이 바뀌나 / 어떤 혜택을 받을 수 있나
3. 참여 방법   자격 조건 / 신청 방법 / 알아볼 수 있는 공식 루트
4. 예상 효과   공식 설명 자료 요약 또는 우리가 예측하는 효과(편리성·경제성 등)
5. 요약
```

- **2와 3이 중심이다.** 금액·기간·조건·절차를 정확히 쓴다.
- 4에서 **우리 예측을 쓸 때는 사실과 구분되게** 쓴다. 공식 자료 요약과 우리 해석을 한 문장에
  섞지 않는다.
- 3의 "공식 루트"는 실제 URL이다. 지어내지 않는다.
- 이 유형은 **분량 상한을 적용하지 않는다**.

## 7. 육아 (2026-09-23 신설)

```
1. 경험 오프닝  우리 집에서 있었던 일, 또는 이 주제를 찾아보게 된 계기
2. 공통 상황    이 시기 부모들이 공통으로 겪는 것 / 사람들이 실제로 묻는 질문
3. 확인된 정보  의료·공공기관 기준 — 시기·수치·조건
4. 해보니 어땠나  우리 집에 적용한 경험 / 사람들이 쓰는 방법
5. 주의할 점    예외, 하면 안 되는 것, 병원에 가야 하는 신호
6. 요약
```

- **이 흐름만 1인칭 경험이 구조의 일부다.** 다른 유형에서 "저도 궁금해서 찾아봤어요"는 금지지만,
  여기서는 화자가 실제로 쌍둥이를 키우는 부모라 진짜 목소리다(`writer.md` §2).
- **경험을 지어내지 않는다.** `episode` 입력이 없으면 1·4를 창작하지 말고, 2(사람들이 실제로 묻는
  질문)로 오프닝을 대신한다. 그래도 안 서면 **초안을 멈추고 사람에게 에피소드를 요청한다**
  (`writer.md` §3).
- **3과 5는 의학 정보다.** `official`/`medical` 등급 근거로만 쓰고, 커뮤니티 근거를 단정하지
  않는다. 의료 판단을 대신하지 않는다(`facts-and-hedging.md`).
- 5를 빼지 않는다. 육아 정보에서 "하면 안 되는 것"이 가장 실용적이다.

## 8. 사건·사고 — 이 문서를 쓰지 않는다

`category: incident`(사망·범죄·재난·수사/재판)는 **`prompts/writing/style/incident.md`와
`writer.md` §2-1이 규격이다.** 무죄추정·신원 보호·자극적 세부 금지·후킹 제목 금지가 그대로다.

§5와 헷갈리기 쉬우니 선을 긋는다(2026-09-23 확정).

```
§5 사회 이슈  제도·소비·커뮤니티 논쟁처럼 사람이 다치지 않은 사안
§8 사건·사고  사망·범죄·재난·수사/재판이 얽힌 사안
```

**애매하면 §8이다.** 잘못 쓰는 비용이 그쪽이 훨씬 크다.

## 9. 저장 전 자문

1. 이 원고가 어느 흐름인지 하나로 말할 수 있는가? 둘을 섞지 않았는가.
2. 단계 **순서**가 맞는가. (재료 사정으로 합치거나 쪼갠 것은 괜찮다)
3. 그 유형의 **중심 단계**에 가장 많은 분량이 갔는가.

   ```
   작품 3·4   인물 2   행사 2·4   제품 2·3   이슈 2·3   정책 2·3   육아 3·4
   ```
4. 마지막 요약에 소제목을 달지 않았는가. 앞 문단을 그대로 반복하지 않았는가.
