묶음에서 "기획에 없는 자리는 마커대로"로 고친다.

## 문제 1 — 기획이 바꿔도 선택이 옛 대상을 본다 (P0, 코드 버그)

### 무슨 일이 있었나

자리 1에 대한 사용자 댓글:

> 이 이미지가 왜 서울고등법원 청사 외관이어야 하나요? (…) 이 문단을 키워드 하나로 정리하면
> '오세훈 서울시장'입니다.

**기획은 이미 그렇게 판단했다.** 수집 기록에 그대로 남아 있다.

```
ℹ️ 기획이 바꿨습니다 → 오세훈 서울시장 단독 사진 · 검색어 오세훈 서울시장 ·
   청사 외관은 요약(구형)을 보여주지 못하고 주인공이 한 번도 없을 위험이 있어…
```

그런데 결과는 **빈 자리**였고, 비운 이유가 이렇게 적혔다.

```
후보 4장 중 쓸 만한 것이 없어 비웠습니다: 이 자리는 서울고등법원 청사 외관을 요구하는데,
후보 4장은 모두 연설하거나 발언하는 오세훈 시장의 상반신 사진이다.
```

**정확히 기획이 요구한 사진 4장을 받아 놓고, 기획이 버린 옛 기준으로 전량 탈락시켰다.**

### 원인

`planImageSlots`의 결과 중 **검색어만** 수집 단계로 넘어간다
(`collectWebImages.ts:881`, `options.planQueries`). 자리의 `description`은 여전히 집필자 마커
원문(`항소심이 열린 서울고등법원 청사 외관`)이고, 그것이 **선택 에이전트의 판정 기준**이 된다.
3단계 배선에서 검색어만 연결하고 대상을 연결하지 않은 것 - 제 설계 누락이다.

### 수정

`WebImageSlot`에 기획 필드를 더하고, **있으면 마커보다 우선**한다.

```ts
type WebImageSlot = {
  index: number;
  description: string;       // 집필자 마커 (폴백)
  planSubject?: string;      // ★ 기획이 정한 대상 - 있으면 이것이 판정 기준
  planCaution?: string;      // ★ 기획의 주의사항 ("표정이 과한 사진 피하기")
  planRecency?: Recency;     // ★ 문제 3에서 추가
  query?: string;
  context: string;
};
```

- `buildPrompt` / `defaultChooseImage`: 자리 설명을 `planSubject ?? description`으로 쓴다.
  `planCaution`은 그 자리 바로 아래 한 줄로 붙인다.
- 캡션도 `planSubject` 기준으로 다시 쓴다(지금은 마커 설명을 다듬어 쓴다).
- 폴백은 그대로 - 기획이 없거나 실패하면 마커를 본다.

이것만 고쳐도 **자리 1은 저절로 찬다.** 후보는 이미 맞게 들어와 있었다.

> 왜 P0인가 — 기획 단계를 어제 켰으므로, 지금 모든 원고에서 "기획이 바꿨습니다"라고 적힌 자리는
> 전부 이 불일치를 안고 돌고 있다. 기획이 대상을 바꿀수록 빈 자리가 늘어난다.

## 문제 2 — 언론사 기사 캡처 폐지 (P0)

### 사용자 결정

> 기사 페이지 캡쳐를 사용하기로 한 이후 **너무 남발되고 있습니다.** 언론사 기사 페이지 캡쳐는
> 더이상 쓰지 않겠습니다. 기존 규칙에서 삭제하거나, 아니면 금지 규칙으로 업데이트 해주세요.

실제로 이 원고는 **6자리 중 4자리가 기사 화면 캡처**였다(YTN·한국일보·아시아투데이·아시아경제).
사용자는 각 자리마다 대안까지 적어 줬다.

| 자리 | 지금 (폐지) | 사용자가 말한 대안 |
|---|---|---|
| 2 | YTN 기사 화면 | — (자리 재설계) |
| 4 | 한국일보 기사 화면 | 검색어 **`오세훈 1000만원`** |
| 5 | 아시아투데이 기사 화면 | **`정치자금법 위반` 인포그래픽** |
| 6 | 아시아경제 기사 화면 | 검색어 **`오세훈 시장 활동`** |

### 무엇을 금지하고 무엇을 남기나

**금지**: 언론사·포털 뉴스 기사 페이지 캡처. 헤드라인 캡처도 같다.

**유지**: 공공기관·공식 홈페이지·예매·신청·순위 차트 페이지 캡처.
`페이지 캡처` 자체를 없애지는 않는다 - 송민호·청년미래적금 원고가 공식 안내 페이지 캡처로
자리를 전부 채운 모범 사례였다(드라이런 문서 ⑨⑩).

### 고칠 곳

| 파일 | 지금 | 바꿀 것 |
|---|---|---|
| `prompts/images/image-maker.md` §2 표 | 2순위 설명에 "기사 헤드라인" | 삭제. **금지 한 줄 추가** |
| 같은 파일 §4-4 2번 | "언론사 기사 헤드라인 화면 캡처를 **적극 활용**한다" | **정반대로 교체** |
| `prompts/research/researcher.md` §11 | 사건사고는 기사 캡처를 적극 쓰라고 적혀 있다(362~363행) | 삭제. 공식·공공 URL만 적는다 |
| `prompts/writing/rules/images.md` | 판정 순서에 기사 캡처가 열려 있다 | 금지 명시 |
| `prompts/writing/writer.md` 체크리스트 | `법령·정부 포털 화면 캡처 0개` | **`언론사 기사 화면 캡처 0개`** 추가 |

### 코드 집행 (규격만으로는 또 샌다)

`capturePagesForJob`에서 **언론사 URL을 거부하고 웹 검색으로 강등**한다.

- 차단: 주요 언론사 도메인 + 포털 뉴스 경로(`n.news.naver.com`, `v.daum.net`) +
  호스트에 `news`·`press`가 들어가는 경우
- **예외**: 사용자가 이미지 수정에서 직접 찍어 준 URL은 통과시킨다
  (2026-09-22 결정 "사용자 지시가 마커보다 우선")
- 거부하면 수집 기록에 남긴다 - `⚠️ 언론사 기사 캡처는 쓰지 않습니다 → 웹 검색으로 돌렸습니다`
- fail-open: 판단이 안 서면 통과시키고 기록만 남긴다

> 도메인 목록은 유지보수가 든다. 1차 방어선은 리서치가 기사 URL을 §11에 **적지 않는 것**이고,
> 코드는 2차 방어선이다.

## 문제 3 — 자리의 대상은 "문단 한 키워드"에서 나온다 (P1)

> 이 문단을 키워드 하나로 정리하면 '오세훈 서울시장'입니다. 즉, **오세훈 서울시장만 나오면
> 됩니다.** '오세훈 서울시장' 키워드로 검색해서 나오는 **10/2일자 이미지들**이 후보가 되어야 합니다.

기획 규칙에 두 개를 더한다(현재 R1~R8).

**R9 — 문단을 키워드 하나로 압축한 뒤 대상을 정한다.**
그 키워드에 사람이 있으면 **사람이 대상**이다. 사건·장소·제도는 사람 다음이다.

**R10 — 건물·청사 외관으로 대역하지 않는다.**
법원·검찰·시청 청사 외관은 **건물 자체가 쟁점일 때만** 쓴다. "어디서 열렸다"는 문장은 사진이
필요 없다. 지금 자리 1이 그 경우였다.

**당일성** — 기획 출력에 `recency` 필드를 더한다.

| 값 | 언제 | 수집이 하는 일 |
|---|---|---|
| `today` | 당일 구형·선고·발표 | 네이버 이미지 검색을 `sort=date`로 한 번 더 돌려 후보에 섞는다 |
| `recent` | 최근 몇 달 안의 활동 | 같다. 선택 프롬프트에 "최근 사진 선호" 한 줄 |
| `any` | 인물 프로필, 작품 스틸 | 지금과 같다(`sort=sim`) |

`searchNaverImages`는 `sort: "sim"` 고정이라 인자 하나만 열면 된다. 후보를 번갈아 섞는 구조
(`interleave`)가 이미 있어 질의를 하나 더 붙이는 것으로 끝난다.

## 문제 4 — 공인 사건에서 AI 일반 장면으로 도피한다 (P1)

자리 3에 대한 댓글:

> 이 문단에서는 여론조사 혐의를 보여줄 필요가 없습니다. **'명태균 + 오세훈 + 김한정' 키워드**로
> 검색해서 나오는 사진을 쓰면 됩니다.

기획은 여기서 **AI 생성 콜센터 장면**으로 돌렸다("특정 인물이 필요 없는 범용 상황이라 웹 검색보다
AI 생성이 안전하며"). 그 판단의 출처는 현재 규격이다.

```
### 4-4. 사회·사건사고·일반 이슈
1. 실존 인물 사진을 지양한다. (…) 이 카테고리에서 AI는 폴백이 아니라 기본 선택지다.
```

**이 규칙은 피해자·어린이·일반인 피의자를 보호하려고 만든 것인데, 공인 사건에 그대로 적용됐다.**
오세훈·명태균·김한정은 실명과 얼굴이 이미 전국에 보도된 사람들이다. 여기서 AI 콜센터 사진을
넣으면 보호가 아니라 **내용과 무관한 장식**이다.

### 수정 — §4-4를 두 갈래로 쪼갠다

| 대상 | 방침 |
|---|---|
| **보호 대상** — 피해자, 미성년자, 일반인 피의자, 신원 비공개 | 지금과 같다. 실사진 쓰지 않고 AI 생성이 기본 |
| **공인** — 정치인·고위공직자·기업인·연예인의 **공적 활동과 사건** | **당사자 실사진을 쓴다.** AI 일반 장면으로 대체하지 않는다 |

**R11 신설 — 사건 당사자가 둘 이상이면 당사자 이름을 묶은 검색어를 먼저 쓴다.**
`명태균 오세훈 김한정`처럼. R7(두 인물을 한 자리에 요구하지 않는다)과 충돌하는 것처럼 보이지만
다르다 - R7은 **함께 찍힌 사진이 세상에 없을 때** 쪼개라는 것이고, R11은 **사건으로 묶여 함께
보도된 인물들**이라 같은 기사 사진에 함께 나올 가능성이 높은 경우다. 기획이 R11로 먼저 시도하고,
후보가 비면 R7로 쪼갠다.

## P2 — 인포그래픽 범위 확대

> 이 문단의 이미지라면 **'정치자금법 위반'에 대한 인포그래픽**을 만들어서 넣겠습니다.

현재 §9는 **행사·정책**에 한해 허용한다. 여기에 한 갈래를 더한다.

**법률·혐의·처벌 기준** — 혐의 구조, 적용 법조, 형량 구간, 절차 일정.
이 원고에는 쓸 자리가 분명하다.

- `정치자금법 위반` 혐의 구조 (의뢰 → 대납 → 공표/비공표 10건)
- `벌금 100만 원 이상 확정 → 피선거권 상실 → 시장직 상실` 흐름도
- 1심 벌금 1000만 원 ↔ 2심 구형 징역 1년 6개월 비교 막대

**본문 표를 그대로 옮기는 것은 계속 금지**다(2026-09-30 결정 유지). 숫자가 본문과 한 글자도
달라서는 안 된다는 규칙도 그대로다.

기사 캡처 4자리를 뺀 빈자리를 **인물 검색 2~3자리 + 인포그래픽 1~2자리**가 메우는 그림이다.
