이 문서를 받은 세션이 **blog-automation 팀장 세션**이다. 앞 팀장 세션(2026-10-27 개시)이 11/05에
컨텍스트와 툴 적재량 때문에 교체되면서 넘긴다. 읽는 순서는 아래 §1 → §2이고, 나머지는 필요할 때
찾아 쓰는 지도다.

## 1. 당신이 할 일과 하지 않을 일

사용자는 **이 세션에만 지시한다.** 당신이 조사·설계·발주·수합·PR 병합·배포·보고를 맡고, 사용자는
승인과 방향 결정만 한다. 하위 세션에 직접 말을 걸지 않으므로, 하위 세션의 결과는 당신이 받아서
검증하고 사용자에게 한 번에 보고한다.

| 당신이 직접 한다 | 하위 세션에 발주한다 |
|---|---|
| 기획·설계·우선순위 결정 | 설계가 끝난 구현 |
| 실측 해석(숫자가 무엇을 뜻하는가) | 측정 스크립트 작성·실행 |
| 사고 진단(원인이 불명확할 때) | 명세가 분명한 수정 |
| PR 리뷰·병합·배포 | 테스트 보강·리팩터링·문서 작성 |
| 사용자 보고·승인 요청 | 자료 조사·수집 |

구분 기준은 **"무엇을 만들지 이미 정해졌는가"** 하나다. 정해졌으면 하위 세션, 정하는 일이면 당신이다.

### 발주 규칙 (2026-11-05 실측으로 정한 것)

- **PR 하나 = 하위 세션 하나.** 파일 단위로 쪼개지 마라. 하위 세션도 각자 매 요청 **65k 고정비**를
  낸다(시스템 툴 29.9k + MCP 툴 23.6k + 스킬 9.9k + 시스템 프롬프트 12.1k + MCP 지침 1.7k). 세션 3개로
  쪼개면 바닥값만 195k다.
- **모델은 난이도별로**: 구현·테스트·문서는 Sonnet, 설계가 섞인 것만 Opus.
- `context`는 보통 `"fresh"`. 이 대화의 맥락이 꼭 필요할 때만 `"fork"`.
- 읽기만 하는 세션은 `use_worktree: false`로 체크아웃을 공유해도 되지만, **코드를 쓰는 세션은 반드시
  worktree**다. 같은 파일을 두 세션이 만지면 덮어쓴다(§3).

**이것이 지난주 실제로 어긴 규칙이다.** 위임이 11/01(PR #37, `focus-revision` 세션)에서 끊기고
PR #41~#56을 전부 팀장 세션에서 Opus로 직접 구현했다. 토큰 소모가 눈에 띄게 빨라진 원인이 이것이다.
구조는 문제가 없었고 실행만 멈췄다. 복원하라.

## 2. 승인 경계 — 외워야 하는 부분

사용자 승인 **없이는 금지**(CLAUDE.md·AGENTS.md 원문):

- Supabase migration 적용 또는 migration history 변경
- 원격/운영 DB `insert`·`update`·`delete`·backfill·cleanup
- Telegram/Kakao 등 외부 메시지 발송 또는 설정 변경
- production 배포, 유료 결제·업그레이드
- 파괴적 Git 작업, 원격 push, merge
- final 6-factor scoring·relevance·clustering 로직 변경

**발행 게이트 환경변수**는 승인 없이 건드리지 않는다: `BLOGGER_ENABLED`, `TISTORY_PUBLISH_MODE`.
(`BLOGGER_AUTO_PUBLISH`는 존재하지 않는 변수다 — 과거에 이것을 찾다 헤맨 적이 있다.)

**비밀 파일은 열지 않는다**: `.env`, 인증 토큰, Creator Advisor 로그인 프로필. 값이 필요하면 키 이름만
확인하고 사용자에게 묻는다.

**merge는 사용자가 말할 때만.** "구현해줘"는 merge 승인이 아니다. 11/05에 PR #57을 지시 없이 병합하려다
자동 모드 분류기에 막혔다 — 분류기가 맞았다.

승인이 필요하면 **사용자에게 떠넘기지 말고, 승인을 받은 뒤 당신이 직접 실행한다.** 이것도 규칙이다.

## 3. 체크아웃 지도 — 남의 작업을 밟지 않는 법

```
/Users/wooahpapa/blog-automation/prod            main (6c9dae3)  ← 운영 기준. 배포·확인용
/Users/wooahpapa/blog-automation/repo            detached        ← 임시
/Users/wooahpapa/blog-automation/tistory-draft   feat/tistory-draft-first  ← 병합 완료, 잔존
/Users/wooahpapa/blog-automation/viewer-publish  docs/humanize-skill       ← 병합 완료, 잔존
```

- `prod`는 **운영 기준 체크아웃**이다. 여기서 기능 브랜치를 만들지 마라. `git pull`로 main에 맞춰 두고
  배포 확인에만 쓴다.
- 다른 세션의 미커밋 변경이 `prod`에 보이면 **손대지 않는다.** 11/05에 `syncGcpBillingCli.ts`가 그렇게
  떠 있었고(지금은 `6c9dae3`로 커밋됨), 건드리지 않은 것이 맞았다.
- **`git stash` 금지.** stash 스택이 모든 worktree와 공유되고 다른 세션이 동시에 pop한다. 작업을 잠시
  치워야 하면 임시 WIP 커밋을 쓴다.
- 쉘 작업 디렉터리가 수시로 초기화된다. **항상 절대경로**나 `cd <abs> && ...` 형태로 쓴다.

**맥미니**(수동 발행·폴러·조사 실행):

```bash
ssh wooahpapa@100.106.42.113   # Tailscale. 구 100.120.26.5는 불통
# 저장소는 ~/blog-automation/prod  (~/blog-automation 아니다)
```

폴러 plist(`com.blogautomation.tistory-poll.plist`)는 `StartInterval 60`으로 매 주기 소스를 다시 읽는다.
배포는 **`git pull`만 하면 되고 plist 리로드는 필요 없다.** 합의되지 않은 plist는 켜지 마라 — 남의
세션 작업이 돌아간다.

## 4. 배포 경로 세 개

| 바뀐 것 | 배포 방법 |
|---|---|
| GitHub Actions 워크플로·`src/**` | main 병합으로 끝 |
| `cloudflare/telegram-relay/**` | **`npx wrangler deploy` 필수.** 병합만으로는 안 바뀐다 |
| 원고 뷰어 페이지 | `manuscripts-refresh.yml`이 push에 자동 발화(경로 조건 있음) |
| 맥미니에서 도는 것 | 맥미니 `~/blog-automation/prod`에서 `git pull` |

`schedule.ts`와 `wrangler.toml`은 **같이** 바뀌어야 한다. 새 cron 문자열을 `schedule.ts`에만 넣으면
Worker가 그 cron으로 깨어나지 않는다.

### cron 슬롯 — 무료 플랜 5칸 중 4칸 사용, 마지막 1칸은 예약

| cron (UTC) | KST | 돌리는 것 |
|---|---|---|
| `0 9,10,11,12 * * *` | 18·19·20·21시 | 키워드 수집 4회차(시간별로 다름) + `watchdog` |
| `30 0 * * *` | 09:30 | `analytics-search` · `kscene-image-health` · `tistory-inventory` |
| `0 1 * * 1` | **일요일** 10:00 | `analytics-index-health` · `style-learn` |
| `0 18 * * 6` | 일요일 03:00 | `storage-cleanup` (기본 dry-run) |

⚠️ 세 번째 줄은 표현식이 월요일(`* * 1`)인데 **실제 발화는 일요일**이다(3주 연속 실측). 월요일에서 run을
찾으면 없다. 표현식은 건드리지 않기로 했다.

회차가 빠지면 **githubstatus.io 타임라인과 대조**한다. 11/04에 GitHub dispatch 장애로 회차가 빠졌고,
Worker 로그는 토큰 권한이 없어 볼 수 없다. 자정 전이면 재발행해도 그날 분으로 집계된다.

## 6. 토큰 관리 — 교체의 이유

매 요청에 **약 65k**가 고정으로 다시 실린다. 11/05에 줄인 것:

- claude.ai 커넥터 4개 끄기(툴 204개분)
- moai 플러그인 MCP 서버 3개 끄기(`korean-stats` 14 · `archhub` 12 · `korean-law` 10 = 36개)
- 사용량 0인 로컬 플러그인 4개 비활성

플러그인 MCP 서버의 on/off는 **`~/.claude.json` → `projects["<경로>"].disabledMcpServers`**에 있고
`plugin:<플러그인>:<서버>` 형태다. `/mcp disable <서버>`가 같은 키를 쓴다. **경로별로 따로** 저장되므로
`/Users/wooahpapa/blog-automation`, `.../repo`, `/Users/wooahpapa/Documents/blog-automation` 셋을 다 손봐야
한다. 돌고 있는 세션도 이 파일을 쓰므로 편집은 **원자적 교체**(임시 파일 + `os.replace`)로 한다.
이미 disabled로 보이는 서버 중 일부는 사용자가 끈 것이 아니라 `${user_config.X}` 자격증명이 없어
**자동으로 꺼진 것**이다.

**세션을 오래 끌지 마라.** 긴 대화는 매 요청에 전체가 다시 실린다. 주제가 끝나면 교체한다. 이 문서가
교체 비용을 낮추기 위해 있다.

## 7. 반복해서 밟은 함정

- **스택 PR**: base PR을 squash 병합하면 자식 PR이 두 PR이 함께 건드린 모든 파일에서 충돌한다. 해법은
  `git merge origin/main` + HEAD 쪽 유지다. **`git checkout --ours`는 쓰지 마라** — 같은 파일 안에서
  main이 자동 병합한 hunk까지 버린다.
- **브리프 범위 드리프트**: 2차 브리프를 다시 쓰면 주제가 바뀐다(10/30 부산 특산품 사고). 지금은
  브리프 가드(a08cbb8) + 범위 게이트(9b1bfb5) 두 겹으로 막혀 있다.
- **이미지 배포 경합**: 동시 발행이 앞 글 이미지를 덮어 404를 만든다(10/15·10/31 두 번). 같은 순간에
  출발하면 락이 못 막는다. 복구는 `npm run images:repair-pages`, 감지는 일일 `images:health`.
- **조사 소스 404**는 차단이 아니라 키워드 문장을 URL에 넣은 버그였다(PR #47). 차단을 의심하기 전에
  요청 URL을 먼저 본다.
- **느린 점검은 타임아웃이 아니라 응답 시간**이었다(PR #44, 응답 6.5초 → 병렬 6 + 상한 200).
- **티스토리 매칭은 URL로** 한다. 같은 글이 `/79`와 `/entry/<slug>` 두 주소로 서비스된다.
- **맥미니의 claude 로그인과 클라우드 토큰은 별개**다. 로컬 로그인이 만료되면 사람이 맥 화면에서
  복구해야 하고, 그때까지 맥미니 판정 작업이 멈춘다.

메모리에 기록할 일이 생기면 한 파일 한 사실로 쓰고 `MEMORY.md`에 한 줄을 더한다. 저장소가 이미
기록하는 것(코드 구조·과거 수정·git 이력)은 메모리에 쓰지 않는다.

## 9. 보고 방식

- 일이 끝나면 `wrap_up`으로 **지금 무엇이 참이 되었는지 + 어디까지 왔는지 + 확인하지 못한 것**을 적는다.
  권고는 recap에 쓰지 않는다.
- 사용자의 전제가 실측과 다르면 **맞장구치지 말고 숫자를 들고 반박한다.** 11/05에 "GA4가 자체 통계보다
  적다"는 전제가 방향이 반대라는 것, 10/31에 "경제를 메인으로"·"국방외교가 강하다"가 근거 없다는 것이
  그렇게 갈렸다. 사용자가 전제를 재확인하면 그것은 결정이므로 그대로 따른다.
- 하위 세션의 보고는 **보고일 뿐 증거가 아니다.** diff나 결과를 직접 확인한 뒤에 "됐다"고 말한다.
