# 인포그래픽 샘플 프롬프트 — 품질 판정용 (2026-10-01)

## 왜 이걸 만드는가

2026-09-30에 **AI가 만든 표·인포그래픽 이미지를 전 원고에서 금지**하고 렌더 코드까지 지웠다.
이유는 "본문 텍스트를 그대로 옮겨 둔 것에 불과했고, 글자가 핵심인 이미지는 AI가 글자를 제대로
못 쓴다"였다.

그런데 사용자 규칙 문서(2026-10-01 공유)는 행사·정책 카테고리에서 **인포그래픽을 제작한다**고
적는다. 금지 대상을 "본문 텍스트를 그대로 이미지화만 한 표"로 한정한다.

**둘이 보는 대상이 다를 수 있다.** 사용자 문서가 말하는 것은 픽토그램·그래프가 있는 디자인된
인포그래픽이고, 9월 30일에 지운 것은 본문 표를 그대로 옮긴 표 이미지다. 그래서 **제한적 부활**
(3안)을 고르고, 실제로 그 둘을 AI가 구분해 만들 수 있는지 **샘플로 먼저 확인**한다.

추측으로 정하지 않기 위한 절차다. 결과를 보고 `prompts/images/image-maker.md` §9를 채운다.

## 쓰는 법

아래 프롬프트를 ChatGPT(이미지 생성) 또는 Gemini에 **그대로 붙여넣는다.** 세 유형을 다 해보는
것이 핵심이다 — A형이 실패하고 B·C형이 성공하면 "표는 금지, 픽토그램·그래프는 허용"이라는 선이
데이터로 생긴다. 셋 다 실패하면 9/30 금지를 유지하면 된다.

재료는 실제 원고다(2026-09-30 「청년미래적금 10월 7일 2차 가입 신청」, category=living).
숫자가 실제 값이라 틀리게 그리면 바로 보인다.

## A형 — 표 중심 (대조군, 실패할 것으로 예상)

9월 30일에 금지한 바로 그 형태다. 이게 잘 나오면 금지를 통째로 재검토해야 하고, 못 나오면
"표 형태 금지"는 유지한다.

```
한국어 블로그에 넣을 가로형 인포그래픽 이미지를 만들어줘. 16:9 비율.

제목: 청년미래적금 2차 신청 일정

표 형태로 아래 내용을 정확히 담아줘. 글자는 한글로, 오타 없이.
- 10월 7일 : 출생연도 끝자리 홀수
- 10월 8일 : 출생연도 끝자리 짝수
- 10월 12일~16일 : 누구나
- 10월 19일~11월 13일 : 심사
- 11월 16일~27일 : 계좌 개설

깔끔한 플랫 디자인, 파란색 계열, 흰 배경.
```

---

## B형 — 픽토그램 + 최소 라벨 (3안이 노리는 형태)

글자를 **날짜와 두세 단어 라벨로만** 쓰고 의미는 아이콘과 배치가 전달한다.

```
한국어 블로그에 넣을 가로형 인포그래픽 이미지를 만들어줘. 16:9 비율.

청년 적금 신청 절차를 왼쪽에서 오른쪽으로 흐르는 4단계로 그려줘.
각 단계는 아이콘 하나 + 짧은 한글 라벨 + 날짜만 넣어줘.

1단계: 서류에 체크하는 아이콘 / 라벨 "신청" / 날짜 "10.7~16"
2단계: 돋보기 아이콘 / 라벨 "심사" / 날짜 "10.19~11.13"
3단계: 봉투와 알림 아이콘 / 라벨 "결과 안내" / 날짜 "10.30~11.2"
4단계: 통장 아이콘 / 라벨 "계좌 개설" / 날짜 "11.16~27"

단계 사이에 화살표를 넣어줘. 글자는 위에 적은 것 외에는 넣지 마.
깔끔한 플랫 디자인, 파란색 계열, 흰 배경, 여백 넉넉하게.
```

---

## C형 — 숫자·그래프 중심 (글자 비중 최소)

두 유형을 비교하는 막대 그래프다. 글자는 라벨과 숫자뿐이다.

```
한국어 블로그에 넣을 가로형 인포그래픽 이미지를 만들어줘. 16:9 비율.

적금 두 가지 유형을 비교하는 막대 그래프 두 쌍을 나란히 그려줘.

왼쪽 묶음 제목 "월 납입 한도"
- "일반형" 막대: 50만원
- "우대형" 막대: 70만원

오른쪽 묶음 제목 "정부 기여금"
- "일반형" 막대: 6%
- "우대형" 막대: 12%

막대 위에 숫자를 크게 표시해줘. 일반형은 회색, 우대형은 파란색.
위에 적은 글자 외에 다른 문구는 넣지 마. 흰 배경, 플랫 디자인.
```

---

## D형 — 행사 카테고리 (B형을 행사에 적용)

사용자 문서가 행사 카테고리에도 인포그래픽을 적는다. 같은 기준인지 확인한다.

```
한국어 블로그에 넣을 가로형 인포그래픽 이미지를 만들어줘. 16:9 비율.

행사 기본 정보를 아이콘 네 개로 한 줄에 나란히 보여줘.
각 아이콘 아래에 짧은 한글 라벨과 값만 넣어줘.

- 달력 아이콘 / "기간" / "10.10~10.12"
- 위치 핀 아이콘 / "장소" / "서울 코엑스"
- 티켓 아이콘 / "예매" / "인터파크"
- 지갑 아이콘 / "입장료" / "무료"

위에 적은 글자 외에는 넣지 마. 흰 배경, 플랫 디자인, 따뜻한 주황 계열.
```

## 무엇을 보고 판정하는가

생성된 이미지를 보면서 아래를 확인한다. **B·C형이 ✅ 네 개를 넘기면 제한적 부활이 성립한다.**

| 확인할 것 | 왜 |
|---|---|
| **한글이 깨지지 않았는가** | 9/30 금지의 직접 원인. 자모가 분리되거나 없는 글자가 섞이면 실패 |
| **숫자가 정확한가** | "50만원"이 "5O만원"·"500만원"이 되면 발행 못 한다. 틀린 정보가 이미지로 박힌다 |
| **적지 않은 글자가 생겼는가** | 모델이 빈칸을 제 맘대로 채우는 일이 흔하다. 없는 문구가 들어가면 사실 오류다 |
| **픽토그램이 내용과 맞는가** | 통장 자리에 영수증이 그려지면 의미가 어긋난다 |
| **블로그 폭에서 읽히는가** | 모바일에서 가로 400px 정도로 줄어든다. 그 크기에서 글자가 보이는가 |
| **본문 표를 그대로 옮긴 느낌인가** | 그렇다면 그게 바로 9/30에 지운 것이다. 이미지로 만들 이유가 없다 |

## 판정 후

- **B·C형만 통과** → 3안 확정. `image-maker.md` §9에 "픽토그램·그래프 중심만 허용, 표 형태 금지"로
  적고, 생성 프롬프트 규격(글자는 라벨·숫자만, 문구를 지어내지 말 것)을 §8에 추가한다.
- **A형까지 통과** → 금지 범위를 더 좁힐 수 있다. 다만 숫자 정확도를 더 많은 표본으로 확인한다.
- **전부 실패** → 9/30 금지 유지. 정책·행사의 수치는 계속 본문 목록으로 쓰고, 이미지 자리는 공식
  안내 페이지 캡처나 현장 실사로 돌린다.

어느 쪽이든 **결과 이미지를 남겨 두면** 다음에 같은 논의가 나왔을 때 다시 돌리지 않아도 된다.
