# 네이버 블로그 SEO + AEO + GEO 실행 가이드

> 기준일: 2026-08-31 · 대상: 네이버 블로그 원고 작성·자동화 파이프라인
> 이 문서는 발행 전 원고를 검사하는 **규칙집**이다. 상위 노출을 보장하는 공식이 아니다.

## 0. 신뢰 등급 표기법

네이버는 랭킹 공식을 공개하지 않는다. 아래 모든 규칙에 등급을 붙였다.

| 등급 | 의미 | 다루는 방법 |
|---|---|---|
| `[공식]` | 네이버가 공식 발표·보도자료·가이드에서 밝힌 내용 | 그대로 신뢰 |
| `[관행]` | 실무자·대행사 사이에서 재현성이 확인된 통설 | 기본값으로 적용하되 절대 수치로 믿지 말 것 |
| `[연구]` | 논문·측정 실험 기반 (해외 AI 검색 대상) | 방향성만 차용 |
| `[벤더]` | 특정 업체가 주장하는 수치, 검증 불가 | 참고만, 인용 금지 |

**핵심 원칙 하나**: `[관행]` 수치는 하한선이지 목표가 아니다. "1,500자 채우기"를 목표로 쓴 글은 정보 밀도로 걸러진다.

## 1. 2026년 네이버 검색 환경 (먼저 알아야 할 지형)

2025~2026년에 네이버 검색은 "링크 목록"에서 "AI가 요약해 주고 출처를 붙이는 화면"으로 바뀌었다. 블로그 글 하나를 쓰는 목표도 **클릭 유도**에서 **인용 확보**로 이동했다.

- `[공식]` **AI 브리핑** — 2025년 3월 도입. 검색 답변을 요약해 보여주고, 근거가 된 블로그 원문을 함께 링크한다.
- `[공식]` **네이버 메이트** — 2026년 6월 출범. **AI 브리핑 피인용 횟수**를 중심으로 주제 전문성, 활동성, 콘텐츠 신뢰도, 이용자 반응, 검색 기여도를 종합해 매월 약 3,000명의 창작자를 선정하고 월 30만~1,000만 원을 지급한다(총 200억 원 규모). 인용 횟수는 **2026년 1월부터 누적 집계**된다.
  → 실무적 의미: **네이버가 "무엇을 좋은 콘텐츠로 보는지"를 처음으로 명문화한 목록**이다. 이 6개 항목이 사실상 2026년 랭킹 요소의 공식 요약본이라고 보고 원고를 설계한다.
- `[공식]` 네이버 CDO 발언 기준, 평가는 **개별 포스트가 아니라 창작자의 활동 패턴** 단위로 이뤄지며, 사실 정보와 주관적 의견을 구분해 다룬다.
- `[관행]` **스마트블록** — 검색 결과가 주제별 블록으로 쪼개진다(인기글, 함께 찾는 콘텐츠, 지식스니펫 등). 하나의 대형 키워드 1위보다 **세부 주제 블록 다수 점유**가 유리하다.
- `[관행]` **홈피드** — 검색 외 추천 유입 경로. 검색 최적화만 한 글은 홈피드에서 소비되지 않는다.

### 이것이 원고 규칙에 미치는 영향

1. 한 글에 모든 걸 담지 말고 **세부 주제별로 완결된 글**을 여러 편 낸다 (스마트블록 대응).
2. 문단 하나가 **떼어내도 말이 되는 완결 답변**이어야 한다 (AI 브리핑 인용 단위).
3. 채널 일관성이 개별 글 최적화보다 우선한다 (창작자 단위 평가).

## 2. 랭킹 로직: C-Rank / D.I.A. / D.I.A.+

| 구분 | 평가 대상 | 보는 신호 | 변화 속도 |
|---|---|---|---|
| **C-Rank** | 블로그(채널) 전체 | 주제 집중도, 발행 일관성, 누적 반응, 독창성, 운영 기간 | 느림 (수개월 누적) |
| **D.I.A.** | 개별 문서 | 검색 의도 부합, 문서 완성도, 정보 밀도, 사용자 반응 | 빠름 (발행 후 수일) |
| **D.I.A.+** | 개별 문서 | 질의 의도별 심층 분석, 경험 기반 정보 여부 | 빠름 |

`[관행]` 실전 해석:

- **C-Rank는 티켓, D.I.A.는 순위다.** C-Rank가 낮으면 아무리 잘 쓴 글도 후보군에 못 들어간다. C-Rank가 있으면 D.I.A.가 개별 글을 줄 세운다.
- C-Rank를 올리는 유일한 방법은 **주제 2~3개로 좁혀 꾸준히** 쓰는 것. 잡블로그는 구조적으로 불리하다.
- 새 블로그는 D.I.A.만으로 뚫어야 하므로 **경쟁도 낮은 롱테일 키워드**부터 잡는다.

## 3. 제목 규칙

| 항목 | 권장값 | 등급 |
|---|---|---|
| 길이 | 공백 포함 25~40자 | `[관행]` |
| 메인 키워드 위치 | **앞쪽 1/3 이내** | `[관행]` |
| 키워드 개수 | 메인 1개 + 보조 1개 (총 2개 이하) | `[관행]` |
| 구조 | `메인키워드 + 한정어 + 이득/결과` | `[관행]` |

### 작성 규칙

1. **검색어를 그대로 포함한다.** 변형·띄어쓰기 변경 금지. 사람들이 실제로 치는 형태를 쓴다.
2. **한정어를 붙여 스마트블록을 겨냥한다.** `제주도 여행` (X) → `제주도 3박4일 아이랑 코스` (O). 대형 키워드 단독은 상위 블로그와 정면충돌한다.
3. **질문형·수치형이 AI 브리핑 인용에 유리하다.** `전세보증보험 가입 조건 4가지와 거절 사유`
4. **제목과 첫 문단의 답이 일치해야 한다.** 제목이 던진 질문에 첫 문단이 답하지 않으면 이탈률로 즉시 페널티를 받는다.

### 제목 금지

- 같은 키워드 2회 이상 반복 (`제주도 맛집 제주도 맛집 추천`)
- 특수문자 남발 (`★`, `♥`, `【】` 연속)
- 낚시성 과장 (`충격`, `이것만 하면 무조건`) — 이탈률로 되돌아온다
- 관련 없는 인기 키워드 끼워넣기

## 4. 본문 구조

### 분량

| 항목 | 값 | 등급 |
|---|---|---|
| 최소 | 공백 제외 1,500자 | `[관행]` |
| 경쟁 키워드 실효 구간 | 2,000~3,000자 | `[관행]` |
| 저품질 위험 구간 | 300자 미만 글의 반복 발행 | `[관행]` |

> 분량은 **정보 밀도의 대리 지표**일 뿐이다. 3,000자를 채우려 같은 말을 늘린 글은 D.I.A.에서 떨어진다. "이 문단을 지워도 독자가 손해 보지 않는다"면 지운다.

### 권장 골격 (AEO/GEO와 호환되는 구조)

```
[도입 3~5줄]
  · 1번째 문장 = 검색 질문에 대한 직답 (40~60자 내외, 정의형)
  · 2~3번째 문장 = 왜 이 글이 신뢰할 만한지 (경험/자격/출처)
  · 마지막 줄 = 이 글에서 다룰 것 (목차 예고)

[소제목 1] 사용자의 실제 질문 형태
  · 결론 먼저 → 근거 → 예시 순
  · 3~5줄 단위로 문단 끊기

[소제목 2] ...
  · 표 또는 번호 목록 최소 1개
  · 개인 경험/수치 최소 1개

[소제목 3~7] 소제목은 2~7개 사이

[마무리]
  · 핵심 3줄 요약
  · 관련 글 내부 링크 1~2개
  · 자연스러운 CTA (댓글 질문 유도가 체류/반응에 유리)
```

### 문단 작성 원칙

- **한 문단 = 한 주제 = 3~5줄.** 모바일 화면에서 한 덩어리로 읽히는 크기.
- **각 소제목 섹션은 단독으로 완결되어야 한다.** AI가 그 섹션만 떼어가도 말이 되어야 인용된다.
- **결론을 뒤로 미루지 않는다.** 역피라미드 구조.
- 네이버 블로그 에디터에는 H1/H2 같은 HTML 헤딩이 없다. **소제목 스타일(인용구·굵게·구분선)** 로 시각적 계층을 만들되, 구조는 문장 자체가 갖도록 쓴다.

### 반드시 넣어야 하는 요소 (2026년 기준 차별화 지점)

1. **직접 경험 서술** — 언제, 어디서, 얼마를 주고, 어떻게 됐는지. AI가 합성할 수 없는 유일한 자산이다.
2. **구체적 수치** — "효과가 좋았다"(X) → "3개월 후 문의가 40% 늘었다"(O)
3. **출처 표기** — 정부기관·공식 통계 링크. AI 브리핑 인용 콘텐츠의 상당수가 출처를 명시하고 있다 `[벤더]`
4. **작성/확인 날짜** — "2026년 8월 기준 확인" 한 줄이 신선도 신호가 된다.

## 5. 키워드 밀도와 위치

### 밀도

| 항목 | 값 | 등급 |
|---|---|---|
| 메인 키워드 반복 | 본문 전체에서 **3~5회** | `[관행]` |
| 위험선 | 10회 이상 → 키워드 스터핑 판정 | `[관행]` |
| 밀도 환산 | 대략 1~2% 이내 | `[관행]` |
| 연관 키워드 | 메인 대신 **유의어·연관어로 분산** | `[관행]` |

> `[연구]` 해외 AI 검색 실험에서 키워드 스터핑은 가시성을 **약 8% 떨어뜨렸다**. 반복은 이제 순효과가 마이너스다.

### 배치 위치 (우선순위 순)

1. **제목 앞쪽** — 가장 중요
2. **첫 문단 첫 문장** — 정의형 문장 안에 자연스럽게
3. **소제목** — 2~3개 소제목에 분산 (전부 넣지 말 것)
4. **이미지 대체텍스트/캡션** — 이미지 설명에 1회
5. **마무리 요약** — 1회
6. **태그** — 정확 일치형 1개

### 키워드 설계법

```
메인 키워드 1개        → 제목 + 첫 문장 + 마무리
세부 키워드 2~3개      → 각 소제목 섹션에 하나씩
연관어/유의어 다수     → 본문 전반에 자연 분산
```

- 하나의 글에 대형 키워드 여러 개를 욱여넣지 않는다. **1글 = 1메인 키워드**가 스마트블록 시대의 기본 단위다.
- 같은 키워드로 자기 글 여러 개를 발행하면 **자기잠식(카니발라이제이션)** 이 일어난다. 세부 주제를 쪼개 각각 다른 키워드를 준다.

## 6. 이미지 · 동영상

| 항목 | 권장값 | 등급 |
|---|---|---|
| 직접 촬영 이미지 | **최소 5장** | `[관행]` |
| 이미지 가로폭 | 800~1,200px | `[관행]` |
| 파일 용량 | 장당 500KB 이하 | `[관행]` |
| 동영상 | 1개 이상 (30초~3분) | `[관행]` |
| 이미지 배치 | 3~5줄 텍스트마다 1장 | `[관행]` |

### 규칙

1. **직접 촬영이 원칙.** 다운로드한 사진 재업로드는 유사문서 판정과 저작권 리스크를 동시에 부른다.
2. **메타데이터가 살아 있는 원본**을 쓴다. 촬영 시각·위치 정보가 있는 이미지가 유리하다는 것이 `[관행]`.
3. **캡션을 붙인다.** 이미지 아래 한 줄 설명이 정보 밀도와 키워드 분산에 동시에 기여한다.
4. **AI 생성 이미지만으로 채우지 않는다.** 특히 후기·리뷰 글에서 실사진 부재는 경험 신호 결여로 읽힌다.
5. 동영상은 체류시간을 직접 끌어올린다. 짧은 클립이라도 하나 넣는다.

> **운영 현황(2026-09-01, `prompts/writing/writer.md` §8)**: 이미지 API 자동생성이 보류돼 있어 writer가 직접 촬영을 지시할 수 없다. 대신 `[IMAGE PROMPT:]`에 AI 생성 프롬프트 또는 웹 검색 검색어를 써서 사용자가 그대로 복사해 이미지를 구하게 한다. 웹 검색으로 구한 사진을 그대로 올리는 것은 위 1번(직접 촬영 원칙)·유사문서/저작권 리스크와 여전히 부딪히므로, writer는 공공저작물·보도자료·공식 배포 이미지를 우선 찾도록 검색어를 구성하고 저작권 우려가 있는 소재는 "출처 표기 필요"를 표시하게 돼 있다. 완전한 해결책은 아니고, 임시 절충이다.

## 7. 해시태그 · 태그

| 항목 | 권장값 | 등급 |
|---|---|---|
| 개수 | **5~10개** (최대 30개까지 입력 가능하나 채우지 말 것) | `[관행]` |
| 구성 | 메인 키워드 1 + 세부 키워드 2~3 + 연관어 3~5 | `[관행]` |

### 규칙

- 태그는 **본문에 실제로 등장한 주제만** 단다. 본문과 무관한 인기 태그는 어뷰징 신호다.
- 모든 글에 **동일한 태그 세트를 복붙하지 않는다.** 반복 패턴은 자동 발행으로 읽힌다.
- 태그는 랭킹 요소라기보다 **주제 분류 힌트**로 본다. 태그로 순위가 뒤집히지 않는다.
- 특수문자·띄어쓰기 없는 긴 조합 태그(`#제주도3박4일아이랑가볼만한곳`)는 1~2개까지만.

## 8. 발행 · 운영 규칙

| 항목 | 권장값 | 등급 |
|---|---|---|
| 발행 주기 | 주 2~3회, **일정한 간격** | `[관행]` |
| 주제 범위 | 카테고리 2~3개로 집중 | `[관행]` |
| 초기 반응 관리 | 발행 후 **24~48시간**이 결정적 | `[관행]` |
| 색인 요청 | 네이버 서치어드바이저 수동 등록 | `[관행]` |

- **몰아쓰기 금지.** 하루 5개 발행 후 2주 공백은 어뷰징 패턴에 가깝다. 예약 발행으로 간격을 고르게 만든다.
- **수정은 발행 후 24시간 이후에.** 발행 직후 잦은 수정은 문서 재평가를 유발한다 `[관행]`.
- **과거 글 업데이트**를 파이프라인에 넣는다. 신선도 신호는 신규 발행뿐 아니라 갱신으로도 만들어진다.

| 패턴 | 관리 기준 |
|---|---|
| 광고·협찬 글 비중 | 전체의 **30% 이하** `[관행]` |
| 대가성 표기 누락 | 표시광고법 위반 + 신뢰도 하락 |

| 목적 없는 이모티콘·줄바꿈 도배 | 본문 밀도 희석 |

### AI 생성 원고의 특수 리스크

자동화 파이프라인에서 특히 주의할 것:

1. **템플릿 반복** — 모든 글이 같은 도입부·같은 문단 개수·같은 마무리면 패턴이 탐지된다. 구조에 변주를 준다.
2. **경험 서술 부재** — AI가 가장 못 만드는 것이자 네이버가 가장 크게 보는 것. 실제 경험 데이터를 원고 입력으로 반드시 주입한다.
3. **검증 안 된 수치** — 존재하지 않는 통계·기관명은 신뢰도 신호를 통째로 무너뜨린다. 출처 URL 없는 수치는 쓰지 않는다.
4. **문체 균질성** — 문장 길이가 전부 비슷하면 기계 티가 난다. 장단 혼합.

### 저품질 의심 시 점검 순서

1. `site:blog.naver.com/아이디 키워드`로 색인 여부 확인
2. 최근 3개월 글 중 위 표의 즉시 위험 항목 해당분 비공개 전환
3. 1,500자 이상 원본 콘텐츠를 주 2~3회 규칙적으로 재개
4. 외부 유입 경로 확보 (검색 외 트래픽으로 신호 다변화)
5. 회복 판단까지 최소 2~3개월 `[관행]`

## 10. AEO — 챗봇이 인용하게 만드는 문장 규칙

**AEO(Answer Engine Optimization)의 목표는 순위가 아니라 인용이다.** ChatGPT·Perplexity·네이버 AI 브리핑은 페이지 전체가 아니라 **1~3문장 블록**을 뽑아 간다. 따라서 최적화 단위는 페이지가 아니라 **문단**이다.

### 규칙 1 — 직답 우선 (Answer-First)

각 섹션의 **첫 문장**이 그 섹션의 답이어야 한다.

```
(X) 요즘 전세 사기가 늘면서 많은 분들이 걱정하시는데요, 오늘은 그중에서도...
(O) 전세보증보험은 집주인이 보증금을 돌려주지 않을 때 HUG가 대신 지급하는 제도다.
    가입 조건은 세 가지이고, 아래에서 순서대로 설명한다.
```

- 직답 문장 길이: **한국어 기준 40~80자, 2문장 이내** `[관행]`
- 형식: `A는 B다` / `A하려면 C를 해야 한다` / `답은 D다`
- 첫 문장에 **접속사·인사말·감탄사 금지.** 인용될 문장에 "안녕하세요"가 들어가면 안 된다.

### 규칙 2 — 소제목을 질문으로

사람이 실제로 검색창에 치는 문장을 그대로 소제목으로 쓴다.

```
(X) 가입 요건
(O) 전세보증보험 가입 조건은 무엇인가요?

(X) 비용
(O) 전세보증보험료는 얼마인가요? (보증금 2억 기준)
```

### 규칙 3 — 자기완결 문단

인용된 문단이 **앞 문맥 없이도 이해되어야** 한다.

- 대명사 금지: "이것은", "위에서 말한", "앞서 설명한" → 주어를 매번 다시 쓴다.
- 각 문단에 **주어·조건·수치**를 다시 명시한다.
- 예: `(X) 이 경우 보증료는 절반이다` → `(O) 신혼부부는 전세보증보험료를 50% 감면받는다`

### 규칙 4 — 추출 가능한 형식

AI는 서술형 산문보다 **구조화된 덩어리**를 선호한다.

- 번호 목록 (순서·절차)
- 표 (비교·조건)
- Q&A 블록 (본문 하단 FAQ 3~5개)
- 체크리스트

> `[벤더]` FAQ 구조 + 40~60단어 답변 조합이 인용 확률을 3.2배 높인다는 주장이 있다. 수치는 검증 불가하나 방향은 다른 자료와 일치한다.

### 규칙 5 — 신뢰 신호를 문장 안에 넣는다

네이버 블로그 에디터는 **JSON-LD·스키마 마크업을 넣을 수 없다.** 따라서 구조화 데이터로 못 하는 일을 **문장으로** 해야 한다.

| 스키마로 하는 일 | 네이버 블로그에서의 대체 문장 |
|---|---|
| `author` | "10년째 세무 상담을 해온 필자가" |
| `datePublished` | "2026년 8월 기준으로 확인한 내용이다" |
| `citation` | "국토교통부 2026년 6월 발표 자료에 따르면" |
| `FAQPage` | 본문 하단 `Q. / A.` 블록 |
| `HowTo` | "1단계 → 2단계 → 3단계" 번호 목록 |

### 규칙 6 — 채널 밖 일관성

AI는 여러 출처가 **같은 말을 하는지**를 본다. 같은 사실을 블로그·인스타·유튜브 설명란·카페 답변에서 일관되게 서술한다. (원문 복붙은 유사문서 위험이므로 **표현을 바꿔 같은 사실을** 쓴다.)

### AEO 문장 체크리스트

- [ ] 각 소제목 섹션의 첫 문장이 그 자체로 답인가
- [ ] 대명사로 시작하는 문단이 없는가
- [ ] 수치에 단위·기준시점·출처가 붙어 있는가
- [ ] 표 또는 번호 목록이 최소 1개 있는가
- [ ] 하단에 Q&A 블록이 3개 이상 있는가
- [ ] 작성자 자격이 본문 어딘가에 문장으로 등장하는가

## 11. GEO — AI 검색 요약에 노출되는 규칙

**GEO(Generative Engine Optimization)는 AEO보다 상위 개념이다.** AEO가 "문장을 어떻게 쓸까"라면, GEO는 "AI 요약 답변 안에 내 콘텐츠가 살아남게 하려면 무엇을 넣을까"다.

### 근거: 측정된 효과 `[연구]`

KDD 2024 GEO 논문(Aggarwal et al., arXiv:2311.09735)이 9가지 기법을 실험한 결과:

| 기법 | 가시성 변화 | 해석 |
|---|---|---|
| **인용문 추가** (Quotation Addition) | 큰 폭 상승 | 전문가 발언을 직접 인용 |
| **통계 추가** (Statistics Addition) | 큰 폭 상승 | 서술을 수치로 대체 |
| **출처 인용** (Cite Sources) | **약 +27%** | 신뢰 가능한 출처 링크 |
| **문장 유창성 개선** (Fluency) | **약 +28%** | 가장 효과가 큰 단일 기법 |
| **권위적 어조** (Authoritative) | 약 +18% | 단정적·전문적 서술 |
| **전문 용어 사용** (Technical Terms) | 약 +18% | 도메인 용어 정확히 사용 |
| **쉬운 표현** (Easy-to-Understand) | 약 +14% | |
| **고유 단어 추가** (Unique Words) | 약 +6% | 효과 미미 |
| **키워드 스터핑** | **약 -8%** | 역효과 |

논문은 GEO 기법 적용으로 가시성이 **최대 40%까지** 향상됐다고 보고한다. 핵심 결론 두 가지:

1. **내용을 추가하는 기법(인용문·통계·출처)이 문체만 손보는 기법보다 강하다.**
2. **키워드 반복은 AI 검색에서 순효과가 마이너스다.** 전통 SEO 습관을 그대로 가져오면 손해다.

### GEO 실행 규칙

**① 청킹 — 인용 단위로 쪼갠다**

- 문단 2~4줄, 소제목 2~7개.
- 각 청크가 하나의 질문에 대응.
- 긴 서술을 표로 변환한다 (표는 AI가 가장 잘 뽑아가는 형식).

**② 1차 데이터를 심는다**

AI가 다른 곳에서 못 구하는 정보가 있어야 인용된다.

- 직접 측정한 수치, 직접 찍은 사진, 직접 겪은 사례
- "N개월 운영 결과 X가 Y% 변했다" 형태의 문장 최소 1개
- 소규모라도 자체 설문·비교 실험 결과

**③ 출처를 문장에 붙인다**

- `"~에 따르면"` 패턴을 의도적으로 사용: `국토교통부 2026년 6월 자료에 따르면`
- 기관명 + 발표 시점 + 수치를 한 문장에 묶는다
- 링크만 걸지 말고 **출처명을 텍스트로 노출**한다 (AI는 텍스트를 읽는다)

**④ 신선도 신호**

- 본문에 "2026년 8월 기준" 명시
- 오래된 글은 수치를 갱신하고 갱신일을 적는다
- `[벤더]` 갱신 타임스탬프가 인용 확률을 1.8배 높인다는 주장 있음

**⑤ 네이버 AI 브리핑 특화 대응**

네이버가 밝힌 인용 창작자 선정 기준(주제 전문성 · 활동성 · 콘텐츠 신뢰도 · 이용자 반응 · 검색 기여도)에 그대로 맞춘다:

| 네이버 기준 | 원고 단계에서 할 일 |
|---|---|
| 주제 전문성 | 카테고리 2~3개 고정, 세부 주제로 깊게 |
| 활동성 | 주 2~3회 규칙적 발행 |
| 콘텐츠 신뢰도 | 출처 표기 + 확인 날짜 + 작성자 자격 |
| 이용자 반응 | 댓글 유도 질문, 발행 후 48시간 관리 |
| 검색 기여도 | 롱테일 질문형 키워드로 미답변 영역 채우기 |

**⑥ 측정**

- 주요 키워드 20~30개를 정해 **월 1회** ChatGPT·Perplexity·네이버 AI 브리핑에 직접 질의해 인용 여부 기록
- 서버 로그/유입 경로에서 AI 크롤러·AI 레퍼럴 확인
- 지표는 순위가 아니라 **인용 점유율(share of voice)**

### GEO 체크리스트

- [ ] 본문에 통계·수치가 3개 이상 있고 모두 출처가 붙어 있는가
- [ ] 전문가 발언 또는 공식 문서 인용이 1개 이상 있는가
- [ ] 다른 어디에도 없는 1차 데이터(경험·측정)가 있는가
- [ ] 기준 시점이 본문에 명시돼 있는가
- [ ] 표가 최소 1개 있는가
- [ ] 키워드 반복이 5회를 넘지 않는가

## 12. 발행 전 최종 체크리스트

원고 자동화 파이프라인의 **게이트**로 그대로 쓸 수 있는 형태.

### A. 네이버 SEO

- [ ] 제목 25~40자, 메인 키워드가 앞쪽 1/3에 위치
- [ ] 제목 키워드 중복 없음, 특수문자 남발 없음
- [ ] 본문 공백 제외 1,500자 이상 (경쟁 키워드는 2,000자 이상)
- [ ] 메인 키워드 본문 반복 3~5회 (10회 미만 확정)
- [ ] 소제목 2~7개, 각 섹션 독립 완결
- [ ] 직접 촬영 이미지 5장 이상, 각 500KB 이하
- [ ] 동영상 1개 이상
- [ ] 태그 5~10개, 전부 본문 주제와 일치
- [ ] 발행 간격이 직전 글로부터 규칙적

### B. AEO

- [ ] 첫 문장이 검색 질문에 대한 직답 (인사말 없음)
- [ ] 소제목이 질문 형태
- [ ] 대명사로 시작하는 문단 0개
- [ ] 하단 Q&A 블록 3개 이상
- [ ] 작성자 자격·경험이 문장으로 명시

### C. GEO

- [ ] 출처 표기된 수치 3개 이상
- [ ] 1차 데이터(직접 경험·측정) 1개 이상
- [ ] 표 1개 이상
- [ ] 기준 시점 명시
- [ ] 인용문 또는 공식 자료 인용 1개 이상

### D. 리스크

- [ ] 타 문서 복사 문장 0 (유사도 검사 통과)
- [ ] 모든 이미지 자체 제작·촬영
- [ ] 동일 원고 타 채널 동시 게재 아님
- [ ] 검증 불가 수치·기관명 0
- [ ] 광고성 글이면 대가성 표기 포함
- [ ] 이전 3개 글과 도입부·구조가 동일하지 않음

## 13. 이 가이드를 쓸 때의 주의

1. **네이버는 공식 수치를 발표한 적이 없다.** 3장~8장의 숫자는 전부 실무 관행이다. 하한선으로만 쓰고, 숫자를 채우는 것을 목표로 삼지 않는다.
2. **알고리즘보다 빠르게 변하는 것은 검색 화면 자체다.** AI 브리핑 도입(2025.03) 이후 블로그 유입 구조가 바뀌었다. 분기마다 실제 검색 결과 화면을 눈으로 확인하고 이 문서를 갱신한다.
3. **2026년의 진짜 차별화 요소는 경험과 1차 데이터다.** 나머지 규칙은 AI도 다 지킬 수 있다. 지킬 수 없는 것만이 경쟁 우위다.
